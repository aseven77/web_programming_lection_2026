# Лабораторная работа №11

## Регистрация пользователей на PHP и MySQL

[Лекция №11](Web-программирование_Лекция_11_Регистрация.md) · [Предыдущая работа: сессии](Лабораторная_работа_10_Сессии.md) · [Следующая работа: вход](Лабораторная_работа_12_Аутентификация.md)

## Что сделаем

Добавим к сайту новостей таблицу пользователей и страницу `register.php`. После заполнения формы в базе появится пользователь с ролью `user`. В этой работе он ещё не входит на сайт — вход добавим в №12.

Путь запроса: форма → POST → CSRF → проверка полей → хеширование → INSERT → 303 → сообщение об успехе.

## Перед началом

1. Используйте локальные PHP 8.0 и MySQL/MariaDB, расширения `pdo_mysql` и `mbstring`.
2. Проверьте чтение новостей из базы `site` и существующий `config.php`, создающий `$pdo`.
3. Сохраните копию своего проекта и базы перед изменениями.
4. Используйте UTF-8 без BOM. В PHP-файлах не должно быть пробелов перед `<?php`.
5. Открывайте страницы через локальный сервер, не через `file:///`.

Готовые файлы для сверки лежат в [examples/auth](examples/auth/README.md). В основной работе дополняйте свой учебный сайт. Готовый комплект нужен, если вы хотите сравнить результат или развернуть отдельную копию.

```text
ваш сайт/
├── config.php       ← существующее подключение $pdo
├── bootstrap.php    ← общая подготовка и функции
└── register.php     ← регистрация
```

## Шаг 1. Создать таблицу пользователей

В phpMyAdmin выберите базу `site`, откройте вкладку SQL и выполните:

<!-- example:schema.sql -->

```sql
-- Выберите учебную базу site в phpMyAdmin перед выполнением.
CREATE TABLE IF NOT EXISTS users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(80) NOT NULL,
    email VARCHAR(191) NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    role VARCHAR(20) NOT NULL DEFAULT 'user',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY users_email_unique (email)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

<!-- /example -->

`UNIQUE KEY` запрещает одинаковые email. `password_hash` хранит хеш. Значение роли по умолчанию — `user`. Таблицу `news` не меняем.

Если таблица `users` уже была, `IF NOT EXISTS` её не обновит. Сверьте поля и уникальный индекс. При несовпадении используйте отдельную учебную базу или согласуйте изменение схемы; не удаляйте существующие данные.

**Маленькая проверка:** откройте структуру `users`. Должны быть семь столбцов и уникальный индекс `users_email_unique` по email. Строк пока нет, если таблица новая.

## Шаг 2. Проверить подключение

Продолжайте использовать свой `config.php`. Он должен создавать PDO с режимом исключений и кодировкой `utf8mb4`. Если подключение ещё не настроено, образец:

<!-- example:config.example.php -->

```php
<?php
// Скопируйте в config.php и укажите настройки своей локальной базы.
$pdo = new PDO(
    'mysql:host=localhost;dbname=site;charset=utf8mb4',
    'root',
    '',
    [
        PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
        PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
        PDO::ATTR_EMULATE_PREPARES => false,
    ]
);
```

<!-- /example -->

Замените настройки своими. Пустой пароль здесь — только пример локальной конфигурации. Файл сохраните как `config.php`, а не `config.example.php`. Не добавляйте закрывающий `?>`.

## Шаг 3. Создать общий файл bootstrap.php

Это **полный файл**. Скопируйте весь блок один раз:

<!-- example:bootstrap.php -->

```php
<?php
// Подключать до HTML. Другие страницы не должны повторять session_start().
ini_set('session.use_strict_mode', '1');
session_set_cookie_params([
    'httponly' => true,
    'samesite' => 'Lax',
    'secure' => isset($_SERVER['HTTPS']) && $_SERVER['HTTPS'] !== 'off',
    'path' => '/',
]);
session_start();
require_once __DIR__ . '/config.php';

function auth_e(string $value): string {
    return htmlspecialchars($value, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8');
}

function auth_field(array $data, string $key): string {
    return is_string($data[$key] ?? null) ? $data[$key] : '';
}

function auth_csrf(): string {
    if (!isset($_SESSION['auth_csrf']) || !is_string($_SESSION['auth_csrf'])) {
        $_SESSION['auth_csrf'] = bin2hex(random_bytes(32));
    }
    return $_SESSION['auth_csrf'];
}

function auth_valid_csrf($token): bool {
    return is_string($token) && hash_equals(auth_csrf(), $token);
}

function auth_check_post(): void {
    if ($_SERVER['REQUEST_METHOD'] !== 'POST') {
        header('Allow: POST');
        http_response_code(405);
        exit('Используйте форму с методом POST.');
    }
    if (!auth_valid_csrf($_POST['csrf'] ?? null)) {
        http_response_code(403);
        exit('Токен формы устарел. Вернитесь на страницу, обновите её и повторите действие.');
    }
}
```

<!-- /example -->

### Разбираем по частям

- Настройки cookie и `session_start()` стоят до любого HTML.
- `require_once` один раз подключает PDO из `config.php`.
- `auth_e()` готовит строку для безопасного вывода в HTML.
- `auth_field()` берёт только строку: вместо массива или отсутствующего поля возвращает `''`.
- `auth_csrf()` создаёт токен один раз для сессии, затем возвращает существующий.
- `auth_valid_csrf()` сравнивает присланный токен с серверным через `hash_equals()`.
- `auth_check_post()` останавливает неправильный метод с 405, неправильный токен — с 403.

Названия с `auth_` не конфликтуют с функцией `e()` из лабораторной №6. Эти функции будем повторно использовать в следующих работах.

**Маленькая проверка:** откройте `bootstrap.php` через сервер. Ожидается пустая страница без ошибок. Если видите ошибку PDO — сначала исправьте подключение. Не добавляйте постоянный `echo`: он помешает перенаправлениям.

## Шаг 4. Создать обработчик регистрации

Файл `register.php` состоит из двух блоков. **Блок 1 из 2** — обработчик, от `<?php` до закрывающего `?>`:

<!-- example:register.php#server -->

```php
<?php
require_once __DIR__ . '/bootstrap.php';
$errors = [];
$name = '';
$email = '';
$registered = isset($_GET['done']) && $_GET['done'] === '1';

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    auth_check_post();
    $name = trim(auth_field($_POST, 'name'));
    $email = strtolower(trim(auth_field($_POST, 'email')));
    $password = auth_field($_POST, 'password');
    $confirmation = auth_field($_POST, 'confirmation');

    if ($name === '' || mb_strlen($name, 'UTF-8') > 80) {
        $errors[] = 'Имя должно содержать от 1 до 80 символов.';
    }
    if (strlen($email) > 191 || !filter_var($email, FILTER_VALIDATE_EMAIL)) {
        $errors[] = 'Введите корректный email длиной не более 191 байта.';
    }
    if (strlen($password) < 12 || strlen($password) > 72 || strpos($password, "\0") !== false) {
        $errors[] = 'Пароль должен содержать от 12 до 72 байт без нулевого байта.';
    }
    if ($password !== $confirmation) {
        $errors[] = 'Пароли не совпадают.';
    }

    if (!$errors) {
        try {
            $stmt = $pdo->prepare(
                "INSERT INTO users (name, email, password_hash, role) VALUES (?, ?, ?, 'user')"
            );
            $stmt->execute([$name, $email, password_hash($password, PASSWORD_BCRYPT)]);
            header('Location: register.php?done=1', true, 303);
            exit;
        } catch (PDOException $exception) {
            if ((int) ($exception->errorInfo[1] ?? 0) === 1062) {
                $errors[] = 'Этот email уже зарегистрирован.';
            } else {
                error_log((string) $exception);
                http_response_code(500);
                $errors[] = 'Не удалось создать пользователя. Проверьте журнал сервера.';
            }
        }
    }
}
?>
```

<!-- /example -->

### Что проверить глазами

Сначала вызывается `auth_check_post()`, затем читаются поля. Имя и email очищаются от внешних пробелов, пароль — нет. Пароль проверяется в байтах: от 12 до 72, без нулевого байта. Для имени считаем символы через `mb_strlen()`.

INSERT получает параметры, а роль `'user'` записана в SQL самим разработчиком. Введённый пароль заменяется хешем. При конфликте уникального email код MySQL 1062 превращается в понятную ошибку. Остальные ошибки базы не маскируем под «email занят».

После успеха выполняется 303. Параметр `done=1` отвечает только за текст уведомления: сам по себе он не доказывает наличие пользователя. Результат регистрации проверяем в базе.

## Шаг 5. Добавить форму

**Блок 2 из 2** — добавьте сразу после первого, не удаляя закрывающий `?>`:

<!-- example:register.php#html -->

```php
<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Регистрация</title>
</head>
<body>
<h1>Регистрация</h1>
<?php if ($registered): ?>
    <p>Регистрация завершена. Теперь можно войти в свою учётную запись.</p>
<?php endif; ?>
<?php foreach ($errors as $error): ?>
    <p role="alert"><?= auth_e($error) ?></p>
<?php endforeach; ?>
<form method="post" action="register.php">
    <input type="hidden" name="csrf" value="<?= auth_e(auth_csrf()) ?>">
    <p><label>Имя <input name="name" maxlength="80" required autocomplete="name" value="<?= auth_e($name) ?>"></label></p>
    <p><label>Email <input type="email" name="email" maxlength="191" required autocomplete="email" value="<?= auth_e($email) ?>"></label></p>
    <p id="password-hint">Пароль: 12–72 байта. Латинская буква занимает один байт, русская обычно два. Для первой проверки используйте латинские буквы и цифры.</p>
    <p><label>Пароль <input type="password" name="password" required autocomplete="new-password" aria-describedby="password-hint"></label></p>
    <p><label>Повтор пароля <input type="password" name="confirmation" required autocomplete="new-password"></label></p>
    <button type="submit">Создать учётную запись</button>
</form>
</body>
</html>
```

<!-- /example -->

В скрытом поле передаётся CSRF-токен. Имя и email после ошибки остаются, пароли нужно ввести заново. HTML не должен содержать подставленного значения пароля.

**Маленькая проверка:** откройте `register.php`. Ожидайте четыре поля и кнопку. Пока форму не отправили, таблица не меняется.

## Шаг 6. Первая регистрация

Для локальной проверки используйте вымышленные данные: имя `Анна`, email `anna@example.test`, пароль `StudyPass12345`, такой же повтор. Этот пароль — только учебный пример.

Нажмите кнопку. Во вкладке Network увидите POST с ответом 303, затем GET `register.php?done=1`. В таблице `users` появится одна строка. Роль — `user`, поле `password_hash` содержит длинную строку, а не `StudyPass12345`.

Нажмите F5: число строк не должно увеличиться. Повторите регистрацию с другим email — это уже другая учётная запись.

## Шаг 7. Проверки ошибок и подмен

Каждый опыт выполняйте на своей локальной копии. Для обхода браузерного `required` можно временно убрать его в DevTools; сервер всё равно обязан проверить ввод.

| Действие | Ожидаемый результат |
|---|---|
| Зарегистрировать тот же email ещё раз | Сообщение о занятом email, второй строки нет |
| Использовать `ANNA@example.test` после `anna@example.test` | Тот же конфликт по принятому правилу email |
| Передать имя из пробелов | Ошибка имени, INSERT не выполняется |
| Указать пароль и другой повтор | Ошибка совпадения |
| Указать пароль из 11 латинских букв | Ошибка длины |
| Указать пароль из 73 латинских букв | Ошибка длины, пароль не обрезается молча |
| Удалить скрытое поле `csrf` и отправить форму | HTTP 403, строка не добавлена |
| Переименовать поле `email` в `email[]` через DevTools | Ошибка email без падения PHP |
| Добавить в форму скрытое поле `role` со значением `admin` и новый email | Новый пользователь всё равно получает `user` |
| Ввести имя `<b>Анна</b>` и вызвать ошибку повтора пароля | В поле остаётся текст, тег не выполняется |

После опыта с CSRF обновите страницу, чтобы восстановить форму. После ошибки проверьте и сообщение, и число записей в базе.

## Типичные ошибки

| Симптом | Причина и действие |
|---|---|
| `Table ... users doesn't exist` | SQL выполнен не в той базе; сверить `dbname` |
| `Call to undefined function mb_strlen()` | Включить `mbstring` в локальном PHP |
| `Headers already sent` | Убрать BOM, пробелы и отладочный вывод перед заголовками |
| `Cannot redeclare auth_e()` | Использовать `require_once`, не копировать функции в каждый файл |
| Любая форма получает 403 | Проверить cookie, поле `csrf`, стабильность токена; обновить страницу |
| Дубликат email создаётся | Проверить реальный уникальный индекс, не только текст SQL в отчёте |

## Самостоятельная работа

1. Добавьте пояснение рядом с полем email, что он будет использоваться для входа.
2. Покажите число символов имени при ошибке, сохранив серверную проверку максимума.
3. Со звёздочкой: повторите опыт одновременной регистрации одного email двумя запросами и объясните, почему `UNIQUE` остаётся необходимым.

## Что сдать и критерии

Сдайте `bootstrap.php`, `register.php`, обезличенный образец подключения и SQL-структуру `users`. Приложите таблицу проверок «действие → ожидание → факт», скриншоты успеха и ошибки. Не включайте реальные пароли, cookie и CSRF-токены.
