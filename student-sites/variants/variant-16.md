# Вариант 16. Тематические курсы

Заготовка: Новый навык. Таблица: courses. Поле: topic (Направление). Правило: Web, Дизайн, Данные. Пример: Данные. Записей на странице: 6.

Общие условия и правила самостоятельной работы: [requirements.md](../requirements.md). Дополнительно сдайте план и журнал. На контрольных точках покажите свои решения самостоятельно.

## 1. HTTP и структура (ЛР 1)

Скопируйте 04-courses в проект variant-16. Через локальный сервер откройте главную и каталог. В Network найдите GET страницы и CSS; запишите URL, статус и Content-Type.

**Проверка:** Оба ресурса возвращают 200; страница — text/html, CSS — text/css.

**Самостоятельно:** До начала изменений нарисуйте схему страниц и путь одного GET-запроса: браузер → сервер → ответ. На занятии самостоятельно найдите запрос CSS и объясните два его заголовка.

## 2. Переменные и шаблоны (ЛР 2.1)

Переименуйте страницы интерфейса в PHP, исправьте ссылки и action. Вынесите шапку и подвал в includes/header.php и includes/footer.php. Название «Тематические курсы» задайте переменной.

**Проверка:** Название меняется в одном месте и отражается на всех страницах; старых HTML-ссылок интерфейса нет.

**Самостоятельно:** Сами выберите переменные общего шаблона и отметьте, какие страницы используют их. Перед переносом шапки укажите границы общего и уникального HTML.

## 3. Массив предметной области (ЛР 2.1)

Создайте массив 12 записей с id, title, content, created_at и topic. Поле «Направление»: Web, Дизайн, Данные. Пример: Данные. Если поле шаблона отличается, замените его в формах и карточках.

**Проверка:** 12 разных id. Все значения дополнительного поля соответствуют правилу.

**Самостоятельно:** Придумайте свои 12 записей: не копируйте названия и описания макета. Подготовьте набор данных для пустого результата, нескольких совпадений, одинаковых дат, кавычек и буквального текста с HTML-тегами.

## 4. Циклы и статистика (ЛР 3)

Каталог выведите через foreach, последние три записи — на главной. Функцией вычислите количество записей и среднюю длину заголовка.

**Проверка:** В каталоге 12 карточек, на главной 3; после добавления элемента статистика меняется.

**Самостоятельно:** Самостоятельная особенность варианта: Покажите число курсов каждого направления и предусмотрите направление без курсов. Решение и правило расчёта сначала опишите словами; готовый код этой особенности не выдаётся.

## 5. POST и проверка формы (ЛР 2.2)

Подключите форму admin.php. Проверяйте title (3–120 символов), content (20–3000 символов) и topic (Web, Дизайн, Данные). После ошибки сохраняйте корректно введённые поля.

**Проверка:** Пустой title, короткий content, неверное topic и title[] отклоняются без падения; ошибки видны рядом с формой.

**Самостоятельно:** До написания обработчика составьте свою таблицу из пяти ошибочных вводов: ввод → ожидаемая ошибка. После реализации проверьте её прямым запросом, а не только через форму.

## 6. JSON из массива (ЛР 2.2)

Создайте api.php, возвращающий записи как JSON без HTML. Укажите Content-Type application/json; charset=utf-8.

**Проверка:** JSON разбирается без ошибки; русские буквы читаются; в ответе нет шапки сайта и предупреждений PHP.

**Самостоятельно:** Нарисуйте структуру JSON одной записи и сами выберите названия верхних ключей. Объясните различие успешного ответа и ответа с ошибкой.

## 7. MySQL и PDO (ЛР 4)

Создайте отдельную базу variant_16, таблицу courses (id, title, content, created_at, topic) и contacts. Тип поля topic выберите по правилу варианта. Внесите 12 записей и 2 контакта. config.php должен создавать $pdo.

**Проверка:** Каталог и контакты читаются из БД; изменение в phpMyAdmin видно на сайте. Старую базу лабораторных не удаляйте.

**Самостоятельно:** Составьте схему БД на бумаге: поля, типы, ограничения. Обоснуйте тип дополнительного поля и одну альтернативу, которую вы не выбрали.

## 8. Подробности записи (ЛР 4)

В detail.php получите целочисленный id из GET и прочитайте одну запись параметризованным запросом. Все значения экранируйте при выводе.

**Проверка:** Разные id показывают разные записи. Несуществующий id — 404; id[]=1 и id=abc — 400. Строка <b>Тест</b> выводится текстом.

**Самостоятельно:** На контрольной точке самостоятельно проследите значение id от адресной строки до SQL и HTML. По просьбе преподавателя найдите место, которое формирует 404.

## 9. Создание записи (ЛР 6)

Реализуйте INSERT через параметры PDO, включая topic. После успеха делайте POST → 303 → GET.

**Проверка:** Новая запись видна после перезагрузки. F5 не создаёт дубликат.

**Самостоятельно:** До выполнения нарисуйте последовательность POST → INSERT → 303 → GET. После выполнения покажите её в Network и объясните, почему F5 не создаёт ещё одну запись.

## 10. Редактирование записи (ЛР 6)

Добавьте предварительное заполнение формы по id, проверку и UPDATE всех редактируемых полей, включая topic.

**Проверка:** Меняется только выбранная запись. При ошибке текст не теряется; отсутствие id обработано.

**Самостоятельно:** Придумайте и проверьте один собственный сценарий редактирования помимо основного: например, изменение только дополнительного поля. Запишите ожидание до запуска.

## 11. Удаление записи (ЛР 6)

Добавьте отдельную POST-форму с action=delete и id; перед удалением показывайте понятное подтверждение. GET не должен менять БД.

**Проверка:** Удаляется одна выбранная запись. GET не удаляет; повторное удаление сообщает об отсутствии записи.

**Самостоятельно:** Объясните, почему удаление не должно выполняться через ссылку GET. На занятии покажите, как сервер проверяет id до удаления.

## 12. DOM и события (ЛР 5)

Создайте catalog.js: счётчик видимых карточек и кнопку показа/скрытия кратких описаний. Строки данных выводите через textContent.

**Проверка:** Счётчик соответствует DOM. Кнопка меняет состояние; данные с тегами не исполняются как HTML.

**Самостоятельно:** Самостоятельно выберите подписи кнопки в обоих состояниях. Самостоятельно измените поведение кнопки на занятии: скрывать описания только у выбранной карточки.

## 13. PHP API и fetch (ЛР 7)

Создайте api-courses.php и api-app.php с загрузкой, добавлением и удалением через fetch. Передавайте topic. Показывайте загрузку, успех, пустой список и ошибку.

**Проверка:** Операции обновляют DOM без перезагрузки; Network показывает JSON. Ошибка сети и неверный ввод не выглядят как успех.

**Самостоятельно:** Сначала составьте контракт API и псевдокод fetch словами. После реализации воспроизведите собственный сценарий ошибки и покажите реальный HTTP-ответ.

## 14. Поиск и дополнительный фильтр (ЛР 8)

В catalog.php реализуйте GET q по title и GET topic по дополнительному полю точным совпадением выбранного значения. Контрольное значение: Данные. Для перечислений добавьте select, для даты — input type=date.

**Проверка:** Поиск и фильтр пересекают условия. Невозможный запрос даёт «Ничего не найдено». q длиннее 100 символов и параметры-массивы — 400.

**Самостоятельно:** Придумайте два поисковых запроса и сочетание поиска с фильтром, у которых заранее известен результат. Проверьте их на собственных записях и объясните условия пересечения.

## 15. Сортировка (ЛР 8)

Добавьте sort=new, old, title. Серверный белый список: created_at DESC, id DESC; created_at ASC, id ASC; title ASC, id ASC.

**Проверка:** Все три порядка верны. sort=unknown — 400; непроверенный sort не подставляется в SQL.

**Самостоятельно:** Добавьте две записи с одинаковым первым ключом сортировки. Предскажите их порядок до открытия страницы и объясните роль id в сортировке.

## 16. Пагинация (ЛР 9)

Показывайте 6 записи на странице. COUNT использует те же фильтры. LIMIT/OFFSET передавайте целыми числами. Ссылки сохраняют q, topic, sort; новый поиск сбрасывает page на 1.

**Проверка:** При 12 записях — 2 страниц. page=0, page[]=1 — 400. Завышенный page переводится на последнюю; пустой список без активных переходов.

**Самостоятельно:** На бумаге рассчитайте OFFSET для второй и последней страницы своего варианта. На занятии самостоятельно измените размер страницы и проверьте новый последний переход.

## 17. Сессия и избранное (ЛР 10)

Реализуйте сохранение и удаление id в $_SESSION через POST. saved.php выводит существующие записи. Проверяйте CSRF, после успеха отправляйте 303.

**Проверка:** F5 сохраняет список; повторное добавление не дублирует id; другой браузер имеет отдельный список. Неверный CSRF — 403 без изменений.

**Самостоятельно:** Нарисуйте структуру $_SESSION для двух выбранных id. Покажите, как обработчик предотвращает дубликаты и что делает с id удалённой записи.

## 18. Регистрация (ЛР 11)

Создайте users по ЛР 11 и register.php: name, email, password, confirmation. Пароль — 12–72 байта по правилам ЛР 11, хранится хеш. email имеет UNIQUE. Роль user задаётся на сервере.

**Проверка:** Дубликат email отклоняется. Подменённая роль admin игнорируется. В БД нет открытого пароля, в HTML после ошибки нет значения пароля.

**Самостоятельно:** Назовите два ограничения, которые проверяет PHP, и одно, которое обеспечивает БД. Покажите на своём коде, почему подмена поля role не меняет роль.

## 19. Вход, профиль и выход (ЛР 12)

Реализуйте login.php с password_verify и обновлением id сессии после входа. profile.php показывает только текущего пользователя. Выход — POST с CSRF.

**Проверка:** Гость перенаправляется на вход. Неверный пароль и неизвестный email дают одинаковое сообщение. После выхода профиль недоступен.

**Самостоятельно:** Нарисуйте состояния «гость → вошёл → вышел». По своей схеме объясните, где проверяется текущий пользователь и почему профиль нельзя выбирать чужим id.

## 20. Права и итоговая защита (ЛР 13)

Защитите admin.php и изменения API: только admin меняет записи. Проверяйте роль из БД и CSRF при каждом изменении. Сдайте исходники, SQL структуры и 12 записей, README запуска и отчёт проверок.

**Проверка:** Прямой запрос не обходит права: API 401 для гостя, 403 для user; неверный CSRF — 403. GET API читает публично. Смена admin на user отзывает доступ.

**Самостоятельно:** Пройдите очную защиту: объясните выбранный преподавателем участок, спрогнозируйте результат запроса и выполните небольшое изменение за 10–12 минут. Для своего варианта приготовьте изменение: Вывести сводку только по направлениям с двумя и более курсами.
