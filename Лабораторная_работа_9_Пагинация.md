# Лабораторная работа №9

## Тема: новости по страницам

Теория: [лекция №9](Web-программирование_Лекция_9_Пагинация.md). Подготовка: [лабораторная №8](Лабораторная_работа_8_Поиск_и_сортировка.md).

## Что получится

Создадим `news-pages.php`: на странице не больше трёх новостей, под ними ссылки «Назад» и «Вперёд». Поиск и сортировка будут сохраняться при переходах.

Сначала соберём работающий пример, затем проверим его и самостоятельно изменим размер порции. На работу можно выделить два занятия: первое — сборка и разбор, второе — проверки и самостоятельная часть.

## 1. Подготовьтесь

Нужны PHP 8 с расширениями `pdo_mysql` и `mbstring`, MySQL, браузер и редактор. Используйте знакомую базу `site` и таблицу `news` с полями `id`, `title`, `content`, `created_at`.

`config.php` должен создавать подключение `$pdo`. Если его ещё нет, выполните задание 1 из [лабораторной №6](Лабораторная_работа_6_CRUD.md). Здесь не создаём таблицу повторно и не удаляем старые записи.

Проверьте, что `news-search.php` из работы №8 открывается через локальный сервер и находит новости. Адрес зависит от вашей настройки: например, `http://site.local/news-search.php`. В адресной строке не должно быть `file:///`.

В папке учебного сайта рядом с `config.php` создайте **новый пустой** файл `news-pages.php`. Не вставляйте его код в API или в `news-search.php`.

```text
папка вашего учебного сайта/
├── config.php          — уже есть
├── news-search.php     — результат работы №8
└── news-pages.php      — создаём сейчас
```

Для проверок подготовьте не менее 8 учебных новостей, среди них хотя бы 5 с общим словом в заголовке, например «Тренировка»: «Тренировка 1», «Тренировка 2» и так далее. Существующие записи подходят, если выполняются эти условия; недостающие добавьте через знакомую страницу `admin.php`. Тогда можно проверить и обычный список, и перелистывание результатов поиска. Точные числа 3, 3 и 2 в примерах ниже относятся к набору ровно из 8 новостей; если у вас больше записей, заранее пересчитайте ожидаемые порции.

**Перед кодом посчитайте:** при 8 новостях и порции 3 получатся страницы с 3, 3 и 2 записями. Запишите ответ — позже сравните с браузером.

## 2. Как собирать файл

Ниже четыре блока кода. Вставляйте их **подряд в один `news-pages.php`**. Текст пояснений между блоками в файл не копируйте.

Первый блок открывает PHP, третий закрывает его, четвёртый содержит HTML. Не добавляйте собственные `<?php` между первыми тремя блоками. До четвёртого блока страница ещё не готова показывать список. Сохраняйте файл в UTF-8 без BOM.

### Шаг 1. Проверяем пожелания браузера

Вставьте первым:

```php
<?php
require __DIR__ . '/config.php';

function e(string $value): string {
    return htmlspecialchars($value, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8');
}

$q = $_GET['q'] ?? '';
$sort = $_GET['sort'] ?? 'new';
$rawPage = $_GET['page'] ?? '1';

if (!is_string($q) || !mb_check_encoding($q, 'UTF-8')) {
    http_response_code(400);
    exit('Поисковый запрос должен быть строкой UTF-8. Вернитесь к форме.');
}
$q = trim($q);
if (mb_strlen($q, 'UTF-8') > 100) {
    http_response_code(400);
    exit('Введите не больше 100 символов для поиска.');
}

$orders = ['new' => 'id DESC', 'old' => 'id ASC'];
if (!is_string($sort) || !isset($orders[$sort])) {
    http_response_code(400);
    exit('Неизвестная сортировка. Выберите new или old.');
}
$orderBy = $orders[$sort];

$requestedPage = is_string($rawPage)
    ? filter_var($rawPage, FILTER_VALIDATE_INT, ['options' => ['min_range' => 1]])
    : false;
if ($requestedPage === false) {
    http_response_code(400);
    exit('Номер страницы должен быть положительным целым числом.');
}

$perPage = 3;
```

Большая часть уже знакома по работе №8. `$_GET` — параметры адреса; `??` задаёт запасное значение, когда параметра нет. `$orders` — наш список разрешённых вариантов: браузер передаёт короткое слово, а SQL-фрагмент выбирает сервер.

Новое здесь — `$rawPage` и `$requestedPage`. Первое хранит присланный текст, второе — проверенное число или `false`. Конструкция `условие ? значение1 : значение2` означает «если условие верно, взять первое значение, иначе второе».

`FILTER_VALIDATE_INT` проверяет целое число, а `min_range` запрещает ноль и отрицательные значения. Проверяем тип до фильтра: адрес `?page[]=2` передал бы массив вместо одной строки.

**Остановка:** какой номер получим, если `page` отсутствует? 1. А при `page=кот`? Сообщение об ошибке и HTTP 400, без выполнения следующих шагов.

### Шаг 2. Считаем результаты и вычисляем смещение

Добавьте ниже первого блока, не открывая PHP повторно:

```php
$where = '';
$countParams = [];
if ($q !== '') {
    $where = ' WHERE title LIKE :query';
    $countParams['query'] = '%' . $q . '%';
}

$countStmt = $pdo->prepare('SELECT COUNT(*) FROM news' . $where);
$countStmt->execute($countParams);
$total = (int) $countStmt->fetchColumn();

$totalPages = max(1, (int) ceil($total / $perPage));
$page = min($requestedPage, $totalPages);
$offset = ($page - 1) * $perPage;
```

Разбираем по частям:

- `$where` — условие поиска. При пустом поиске оно пустое, поэтому считаем все новости.
- `$countParams` хранит значение для `:query`. Знаки `%` означают «любые символы до и после», как в работе №8. Пользовательские `%` и `_` тоже остаются шаблонами `LIKE`.
- `fetchColumn()` берёт одно значение из результата. Здесь это количество найденных новостей.
- `ceil()` округляет число страниц вверх. `max(1, ...)` оставляет номер 1 для пустого списка.
- `min()` ограничивает слишком большой запрос последней доступной страницей.
- `$offset` считает, сколько записей надо пропустить.

**Остановка:** пусть `$total = 8`, `$perPage = 3`, а посетитель попросил страницу 50. Получим `$totalPages = 3`, `$page = 3`, `$offset = 6`. Объясните каждое число соседу или запишите рядом в тетради.

### Шаг 3. Получаем только нужную порцию

Добавьте следующим блоком:

```php
$sql = 'SELECT id, title, content FROM news' . $where
    . ' ORDER BY ' . $orderBy . ' LIMIT :limit OFFSET :offset';
$stmt = $pdo->prepare($sql);
if ($q !== '') {
    $stmt->bindValue(':query', '%' . $q . '%', PDO::PARAM_STR);
}
$stmt->bindValue(':limit', $perPage, PDO::PARAM_INT);
$stmt->bindValue(':offset', $offset, PDO::PARAM_INT);
$stmt->execute();
$news = $stmt->fetchAll(PDO::FETCH_ASSOC);

function pageUrl(int $number, string $q, string $sort): string {
    return 'news-pages.php?' . http_build_query([
        'q' => $q,
        'sort' => $sort,
        'page' => $number,
    ]);
}
?>
```

`$where` — та же переменная, что и в подсчёте. Поэтому список и счётчик используют одинаковый поиск. `$orderBy` взят из нашего разрешённого списка, а не вставлен прямо из адреса.

`LIMIT` задаёт размер порции, `OFFSET` — пропуск. Передаём их с `PDO::PARAM_INT`, то есть как целые числа. После `bindValue()` вызываем `execute()` без массива: параметры уже привязаны. [Документация PDO](https://www.php.net/manual/en/pdostatement.bindvalue.php) описывает этот способ передачи значений.

Функция `pageUrl()` строит адрес перехода. Если передать `2`, `PHP`, `new`, получим `news-pages.php?q=PHP&sort=new&page=2`. [Функция `http_build_query()`](https://www.php.net/manual/en/function.http-build-query.php) кодирует символы внутри значений параметров.

**Остановка:** сколько элементов может быть в `$news`? От нуля до трёх. Почему не восемь? Потому что MySQL получил ограничение `LIMIT 3`.

### Шаг 4. Показываем форму, список и переходы

Добавьте после `?>` из предыдущего блока:

```php
<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Новости по страницам</title>
</head>
<body>
<h1>Новости по страницам</h1>

<form method="get" action="news-pages.php">
    <p><label>Слово в заголовке
        <input name="q" maxlength="100" value="<?= e($q) ?>">
    </label></p>
    <p><label>Порядок
        <select name="sort">
            <option value="new" <?= $sort === 'new' ? 'selected' : '' ?>>Сначала новые</option>
            <option value="old" <?= $sort === 'old' ? 'selected' : '' ?>>Сначала старые</option>
        </select>
    </label></p>
    <button type="submit">Показать</button>
    <a href="news-pages.php">Сбросить поиск</a>
</form>

<p>Найдено новостей: <?= $total ?>.</p>
<?php if ($total === 0): ?>
    <p>Ничего не найдено. Измените слово или сбросьте поиск.</p>
<?php else: ?>
    <p>Страница <?= $page ?> из <?= $totalPages ?>.</p>
<?php endif; ?>

<?php foreach ($news as $item): ?>
    <article>
        <h2><?= e($item['title']) ?></h2>
        <p>Номер записи: <?= (int) $item['id'] ?></p>
        <p><?= nl2br(e($item['content'])) ?></p>
    </article>
<?php endforeach; ?>

<?php if ($totalPages > 1): ?>
    <nav aria-label="Страницы новостей">
        <?php if ($page > 1): ?>
            <a href="<?= e(pageUrl($page - 1, $q, $sort)) ?>">← Назад</a>
        <?php endif; ?>
        <?php if ($page < $totalPages): ?>
            <a href="<?= e(pageUrl($page + 1, $q, $sort)) ?>">Вперёд →</a>
        <?php endif; ?>
    </nav>
<?php endif; ?>
</body>
</html>
```

Здесь `e()` выводит пользовательский текст как текст, а `nl2br()` сохраняет его переносы строк в HTML. Даже адрес из `pageUrl()` проходит через `e()`, потому что вставляется в HTML-атрибут.

Условия возле ссылок читаются буквально: «если мы не на первой странице — показать назад», «если ещё не дошли до последней — показать вперёд». При единственной странице переходы вообще не нужны.

**Важная мелочь:** в форме нет поля `page`. После нового поиска или смены сортировки браузер запросит страницу 1. Номер страницы передают только ссылки переходов.

## 3. Первый запуск

Сохраните файл. Откройте адрес своего учебного сайта с окончанием `/news-pages.php`, например `http://site.local/news-pages.php`.

Ожидаемый результат:

1. Видны поле поиска, выбор порядка и кнопка «Показать».
2. Показано общее количество новостей и не больше трёх записей.
3. При количестве больше трёх видна ссылка «Вперёд».
4. Нажатие «Вперёд» меняет `page` в адресе и показывает следующую порцию.

Это обычный переход: страница перезагружается. В этой работе изучаем расчёт порций; `fetch` из работы №7 можно подключить к такой логике позже.

## 4. Проверяем по одному действию

Для каждой строки отметьте «получилось» или запишите фактический результат. Во время проверки переходов не добавляйте и не удаляйте новости в другой вкладке: состав списка должен оставаться одинаковым.

| Действие | Что ожидаем |
|---|---|
| Открыть страницу без параметров | Страница 1, максимум 3 новости, большие `id` сверху |
| При 8 новостях перейти вперёд два раза | По 3, 3 и 2 записи; подпись «Страница 3 из 3» |
| Посмотреть первую и последнюю страницы | На первой нет «Назад», на последней нет «Вперёд» |
| Переключить порядок на «Сначала старые» | Возврат на страницу 1; меньшие `id` идут раньше |
| Найти слово «Тренировка», затем нажать «Вперёд» | `q` и `sort` остаются в URL; список по-прежнему содержит только совпадения |
| С находящейся не на первой странице формы отправить новый поиск | В адресе нет прежнего `page`; показываются первые результаты |
| Найти выдуманное слово `неттакойновости987` | Счётчик 0, понятное сообщение, нет переходов |
| Открыть `news-pages.php?page=999999` при нескольких страницах | Показана последняя доступная страница, адрес сохраняет присланное число |
| По очереди открыть `?page=0`, `?page=-1`, `?page=кот`, `?page[]=2` | HTTP 400 и сообщение о неправильном номере |
| Открыть `?sort=случайный` и `?q[]=PHP` | HTTP 400; нет SQL-ошибки или вывода технических подробностей |
| Ввести в поиск `"<b>текст</b>` | Поле сохраняет текст; теги не создают разметку |
| Изменить `$perPage` на 4 при 8 новостях | Ровно две страницы по 4 записи, третьей пустой страницы нет |

Адреса, начинающиеся с `?`, добавляйте к `news-pages.php`, заменяя старые параметры. Код ответа смотрите в инструментах разработчика: F12 → Network («Сеть») → запрос страницы → Status Code («Код состояния»).

Дополнительно проверьте пустую **выборку** поиском. Удалять все новости ради этого не требуется: ветка программы та же, что и у пустой таблицы.

## 5. Если результат отличается

| Что видно | Что проверить |
|---|---|
| `Undefined variable $pdo` | Подключён ли `config.php`, создаёт ли он именно `$pdo` |
| `Call to undefined function mb_...` | В выбранной версии PHP включено ли расширение `mbstring`; после включения перезапустите локальный сервер |
| `Parse error` | Блоки идут подряд; PHP открыт только первым блоком и закрыт третьим |
| SQL-ошибка рядом с `LIMIT` | Для `:limit` и `:offset` указан `PDO::PARAM_INT`; после привязки стоит `execute()` без массива |
| На второй странице пропал поиск | `pageUrl()` получает и `$q`, и `$sort`; ссылки вызывают именно эту функцию |
| Всегда показывается одна порция | В `OFFSET` передаётся `$offset`, а не постоянный 0; в ссылке меняется `page` |
| Счётчик неверный только при поиске | Оба запроса используют одну переменную `$where` и одно значение поиска |
| Кнопки перехода отсутствуют | Найдено не больше `$perPage` новостей; это нормальный случай |
| Видны исходники PHP | Страница открыта не через работающий PHP-сервер; проверьте адрес и настройки локального сайта |

Не исправляйте все строки сразу. Начните с адреса запроса, затем проверьте значения `page` и `q`, потом строку с ошибкой.

## 6. Самостоятельная часть

### Обязательное небольшое изменение

Установите `$perPage = 4`. Перед запуском посчитайте число страниц для своего количества новостей и запишите формулу. Проверьте первую и последнюю страницы, затем объясните, почему в `$offset` вычитается единица.

Подсказка: менять HTML и тексты SQL не требуется. Они уже используют переменную размера порции.

### Если всё получилось — необязательное задание

Добавьте ссылку «В начало» при `$page > 1`. Используйте `pageUrl(1, $q, $sort)`, чтобы не потерять поиск и сортировку. Проверьте её на второй странице результатов поиска.

## 7. Что сдать

- `news-pages.php` и настройки подключения для локального учебного сайта без паролей от внешних серверов.
- Скриншоты первой и последней страниц, а также второй страницы поиска с видимым адресом.
- Таблицу проверок: действие → ожидаемый результат → фактический результат. Скриншот каждой строки не нужен.
- Один расчёт на своих числах: общее количество, размер порции, число страниц, смещение второй страницы.

## Критерии выполнения

Работа готова, если список делится на порции, переходы не теряют поиск и порядок, новый поиск начинается с первой страницы, пустая выборка понятна пользователю, неверный номер даёт 400, слишком большой допустимый номер показывает последнюю страницу. Подсчёт и список используют одинаковый фильтр; `LIMIT/OFFSET` передаются как целые числа; текст безопасно выводится в HTML.
