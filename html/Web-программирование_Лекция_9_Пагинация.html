Web-программирование. Лекция 9

Пагинация: показываем новости маленькими порциями

Предыдущая тема: поиск и сортировка. Практика: лабораторная работа №9.

Что мы научимся делать

Представьте сайт, на котором уже 200 новостей. Читать их на одной длинной странице неудобно. Научим сайт показывать несколько записей, а под ними — ссылки «Назад» и «Вперёд».

Сегодня всего три новые идеи: посчитать записи, выбрать порцию, построить ссылки. Поиск, PHP и таблица news остаются знакомыми. JavaScript для этой задачи не обязателен: ссылки работают и с обычными HTML-страницами.

1. Вспоминаем путь запроса

В прошлой теме браузер передавал PHP два пожелания: что искать (q) и как упорядочить (sort). Теперь добавится третье: какую страницу показать (page). 

Браузер: «Хочу страницу 2 с новостями про PHP»
    ↓ GET news-pages.php?q=PHP&sort=new&page=2
PHP: проверяет пожелания и рассчитывает, сколько записей пропустить
    ↓ два SQL-запроса
MySQL: сообщает общее количество и отдаёт нужные новости
    ↓
PHP: собирает HTML со списком и ссылками
    ↓
Браузер: показывает страницу

Число 2 в адресе — просьба браузера. Это ещё не доказательство, что вторая страница существует. Сначала PHP проверит значение и посчитает результаты.

2. Аналогия: карточки на столе

Положим на стол восемь карточек. На каждой написана одна новость. За один раз разрешим брать три карточки.

Страница Какие карточки показываем Сколько пропускаем
1 1, 2, 3 0
2 4, 5, 6 3
3 7, 8 6

Такое разбиение называют пагинацией — показом списка по страницам. Последняя порция может быть неполной. Это нормально: девятой карточки у нас нет.

В таблице выше числа обозначают места в отсортированном списке, а не id из базы. Если новость №2 удалили, следующая запись всё равно займёт освободившееся место в списке. Для пагинации не нужны подряд идущие id.

Остановитесь и ответьте: сколько карточек надо пропустить перед второй страницей? Три. Перед первой? Ни одной.

3. Четыре переменные, которые не надо путать

Переменная Простое значение Пример
$total Сколько всего подходящих новостей 8
$perPage Сколько разрешено показывать за один раз 3
$page Какую страницу показываем 2
$offset Сколько новостей пропустить в начале списка 3

$perPage выбирает автор сайта. $page приходит от посетителя. $total узнаём у базы. $offset вычисляем сами.

Ниже — учебные фрагменты для разбора. Не нужно склеивать их в файл: полный порядок сборки будет в лабораторной. 

$perPage = 3;
$page = 2;
$offset = ($page - 1) * $perPage;

Разбираем последнюю строку:

  1. $page - 1: перед второй страницей есть одна полная страница.
  2. 1 * 3: в ней три новости.
  3. Значит, пропускаем три новости и начинаем со следующей.

Перед третьей страницей находятся две полные страницы: (3 - 1) * 3 = 6. Перед первой: (1 - 1) * 3 = 0.

Попробуйте сами: показываем по четыре новости. Какой $offset у третьей страницы? Ответ: (3 - 1) * 4 = 8.

4. Два слова в SQL: LIMIT и OFFSET

SELECT id, title, content
FROM news
ORDER BY id DESC
LIMIT 3 OFFSET 6;

Прочитаем запрос как инструкцию:

  • FROM news — взять новости из нашей таблицы.
  • ORDER BY id DESC — расположить их от большего id к меньшему.
  • LIMIT 3 — вернуть не больше трёх записей.
  • OFFSET 6 — пропустить первые шесть записей этого списка.

Это третья страница при размере порции три. Пропуск ничего не удаляет из базы: мы только выбираем, что прочитать. Синтаксис и использование параметров в LIMIT описаны в справочнике MySQL.

Упорядочивание обязательно для предсказуемого результата. Используем уникальный id: у двух новостей не бывает одного и того же значения. В учебной базе больший автоматически выданный id обозначает позже добавленную запись. Это не обязательно более поздняя дата самого события.

Если сортировать только по времени, несколько записей могут иметь одинаковое время. Тогда для однозначного порядка добавляют второе поле, например ORDER BY created_at DESC, id DESC.

5. Сколько получилось страниц

Сначала посчитаем новости:

SELECT COUNT(*) FROM news;

COUNT(*) возвращает одно число: сколько строк подходит под запрос. Он не возвращает заголовки и тексты. Если ищем PHP, считать нужно только результаты этого поиска: 

SELECT COUNT(*) FROM news WHERE title LIKE '%PHP%';

В PHP пользовательский поисковый текст передадим параметром PDO, как в прошлой теме. Здесь фиксированное слово PHP приведено только для чтения SQL.

Делим число результатов на размер порции и округляем вверх:

$total = 8;
$perPage = 3;
$totalPages = (int) ceil($total / $perPage);

8 / 3 — это примерно 2,67. Две страницы не вместят все новости, поэтому нужна третья. ceil() округляет вверх, а (int) превращает результат в целое число.

Новостей По сколько показываем Непустых страниц
8 3 3
6 3 2
1 3 1
0 3 0

Для пустого результата в нашей программе оставим технический номер страницы 1, но покажем текст «Ничего не найдено» и спрячем переходы: 

$totalPages = max(1, (int) ceil($total / $perPage));

max() выбирает большее число. Это правило интерфейса, а не утверждение, что в пустой базе появилась новость.

6. Почему нужны два запроса

Первый запрос отвечает: сколько всего найдено? Второй: какие записи входят в выбранную порцию?

Представьте библиотекаря. Вы спрашиваете, сколько есть книг про космос. Он говорит: «Восемь». Затем вы просите принести три книги. Число восемь и три принесённые книги — разные результаты.

Поэтому count($news) после загрузки порции не заменяет COUNT(*). На первой странице массив содержит три записи, хотя всего их восемь.

У двух запросов должно быть одинаковое условие поиска. Иначе счётчик скажет «30 результатов», а список покажет только две подходящие новости.

7. Просьбу посетителя нужно проверить

Человек может вручную написать page=кот, page=-4 или page=999999. Сайт должен отреагировать понятно.

В лабораторной договоримся так:

  • параметр page отсутствует — открываем первую страницу;
  • page не является положительным целым числом — показываем ошибку HTTP 400;
  • число допустимое, но больше числа страниц — показываем последнюю доступную страницу.

Для последнего случая используем min():

$page = min($requestedPage, $totalPages);
$offset = ($page - 1) * $perPage;

Если попросили страницу 100, а всего их 3, min(100, 3) даст 3. Вычисляем $offset после этого ограничения. Сам адрес при таком подходе не меняется: в нём может остаться page=100, но подпись на странице будет «Страница 3 из 3».

Нельзя заменять проверку приведением (int): строка "2кот" при таком преобразовании станет числом 2. Программа молча примет неправильный ввод.

8. Передаём LIMIT и OFFSET как числа

В лабораторной используем именованные места для значений:

$stmt = $pdo->prepare(
    'SELECT id, title, content FROM news ORDER BY id DESC LIMIT :limit OFFSET :offset'
);
$stmt->bindValue(':limit', $perPage, PDO::PARAM_INT);
$stmt->bindValue(':offset', $offset, PDO::PARAM_INT);
$stmt->execute();
$news = $stmt->fetchAll(PDO::FETCH_ASSOC);

bindValue() прикрепляет значение к указанному месту. PDO::PARAM_INT сообщает, что передаём целое число. Это важно для количества и смещения. После привязки вызываем execute() без нового массива параметров. Подробнее — в документации PDO.

Проверка ввода и указание типа — разные действия: сначала проверили $page, затем вычислили безопасное смещение, затем передали число в SQL.

9. Ссылки должны помнить поиск

Мы ищем PHP, смотрим сначала новые новости и переходим на следующую страницу. Правильная ссылка сохраняет эти пожелания: 

news-pages.php?q=PHP&sort=new&page=2

Если оставить только page=2, сервер забудет поиск и покажет вторую порцию всех новостей. Для сборки адреса используем http_build_query(): 

$query = http_build_query(['q' => $q, 'sort' => $sort, 'page' => 2]);
$url = 'news-pages.php?' . $query;

Функция собирает параметры и кодирует специальные символы в их значениях. Например, & внутри поисковой фразы не превратится в начало другого параметра. Это поведение описано в справочнике PHP.

При помещении $url в HTML-атрибут href всё равно используем знакомое экранирование htmlspecialchars(): создание URL и вставка в HTML — разные этапы.

При новом поиске начинаем с первой страницы. Поэтому в форме поиска нет скрытого поля page. Иначе после поиска, начатого на пятой странице, мы могли бы пропустить первые результаты.

10. Границы нашего примера

Если другой человек добавил новость между двумя переходами, позиции в списке могут сдвинуться. Это обычное ограничение LIMIT/OFFSET: список не является замороженным снимком. Для небольшой учебной базы этот подход понятен и удобен. Другие способы перелистывания можно изучить позже.

Мы также не загружаем все новости в PHP, чтобы затем отрезать лишние. База сразу возвращает нужную порцию.

11. Проверьте себя

Сначала ответьте своими словами, затем сравните с подсказками ниже.

  1. Всего 11 новостей, по 4 на странице. Сколько страниц?
  2. Сколько пропустить перед третьей страницей при порции 4?
  3. Удалит ли OFFSET 8 восемь новостей?
  4. Почему найденные новости нужно считать с тем же WHERE, что и список?
  5. Чем общее количество результатов отличается от count($news)?
  6. Какие параметры должна сохранять ссылка «Вперёд»?
  7. Почему форма нового поиска не передаёт прежний номер страницы?

Ответы для самопроверки

  1. Три: 4 + 4 + 3.
  2. Восемь: (3 - 1) * 4.
  3. Нет. Он пропустит записи только при чтении результата.
  4. Счётчик и список должны описывать один и тот же набор новостей.
  5. Общее количество относится ко всем совпадениям, а count($news) — только к загруженной порции.
  6. Поисковую строку q, сортировку sort и новый номер page.
  7. Новый поиск начинаем с первых результатов.
