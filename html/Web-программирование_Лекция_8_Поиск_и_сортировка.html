Web-программирование. Лекция 8

Поиск и сортировка: учим сайт находить нужную новость

← Лекция 7: Fetch API · Лабораторная работа №8 →

1. Что уже знакомо и что добавим

Мы уже умеем получать новости из MySQL, выводить их в HTML и работать с формами. В предыдущем занятии браузер обращался к PHP через fetch(). Сейчас потренируем другую полезную возможность: пользователь пишет слово, а сервер выбирает подходящие новости и возвращает готовую страницу.

Для этого занятия достаточно таблицы news из базы site и рабочего config.php, который создаёт соединение $pdo. У новости четыре знакомых поля: id, title, content, created_at. Самостоятельные задания из лабораторной №7 выполнять заранее не требуется.

После занятия вы сможете объяснить три вещи:

  • как слово из формы попадает в PHP;
  • как MySQL находит строки по заголовку;
  • как поставить найденные строки в выбранном порядке.

Результатом будет отдельная страница news-search.php. Она только читает новости. Поиск не создаёт, не исправляет и не удаляет записи.

2. Поиск и сортировка — два разных действия

Представьте коробку с карточками новостей. Сначала берём только карточки, в заголовках которых есть слово «кружок». Затем раскладываем эти карточки от самой новой к самой старой.

Поиск отвечает на вопрос «Какие карточки подходят?». Сортировка отвечает на вопрос «В каком порядке показать подходящие карточки?». После смены порядка карточек не становится больше или меньше.

id Заголовок
11 Кружок рисования
12 Спортивный праздник
13 Кружок робототехники

Ищем «Кружок»: подходят записи №11 и №13. Порядок от новых к старым: 13, 11. Порядок от старых к новым: 11, 13. Запись №12 остаётся в базе, но не входит в результат поиска.

У аналогии есть граница: сервер не перекладывает реальные строки таблицы. Он формирует результат конкретного запроса. Другой посетитель может одновременно искать другое слово и получить свой список.

Остановка. Если поменяли только порядок, может ли исчезнуть подходящая новость? Нет: мы изменили расположение результатов, а не условие поиска.

3. Как браузер передаёт условия

Для чтения используем форму с методом GET:

<form method="get" action="news-search.php">
    <label>Слово в заголовке <input name="q" maxlength="100"></label>
    <select name="sort" aria-label="Порядок новостей">
        <option value="new">Сначала новые</option>
        <option value="old">Сначала старые</option>
    </select>
    <button type="submit">Найти</button>
</form>

name="q" — имя поля для сервера. Букву q часто используют как сокращение от query, «запрос». name="sort" обозначает выбор порядка. Надпись «Сначала новые» видна человеку, а значение new отправляется программе.

После отправки браузер открывает адрес примерно такого вида:

http://site.local/news-search.php?q=Кружок&sort=old

? отделяет параметры от пути страницы. & разделяет параметры между собой. Браузер может показать русские буквы в адресе в виде последовательностей %D0...: это кодирование адреса, а не поломка текста. Обычную форму браузер кодирует сам.

Такой адрес можно сохранить в закладки: в нём записаны и слово, и порядок. PHP получит значения через $_GET. Если q отсутствует, будем считать его пустой строкой. Если sort отсутствует, выберем new.

В лекции №7 ответ содержал JSON, который обрабатывал JavaScript. Здесь ответ содержит HTML, который браузер показывает как следующую страницу. База в обоих случаях остаётся на сервере.

4. Проверяем запрос, как заполненный бланк

Форма похожа на бланк с двумя графами. Но посетитель может вручную исправить адрес и написать sort=banana. Поэтому PHP проверяет значения ещё до обращения к базе.

Наш договор:

Параметр Допускаем Если не передан
q Строку UTF-8 до 100 символов после удаления пробелов по краям Пустую строку
sort Только new или old new

Пустой q означает «покажи все новости». Это допустимое действие, поэтому поле не имеет required. Пробелы по краям удаляет trim(): запрос Кружок становится Кружок. Внутренние пробелы сохраняются.

Нужен и is_string(). Адрес ?q[]=Кружок превращает значение q в массив PHP, а наша страница ждёт одну строку. Мы не пытаемся угадать намерение пользователя: возвращаем HTTP 400 и сообщение «Поисковый запрос должен быть строкой».

mb_strlen($q, 'UTF-8') считает символы, а не байты. Для русских букв это существенная разница. Расширение mbstring уже использовалось в лабораторной №6. Проверка mb_check_encoding() дополнительно убеждается, что строка действительно имеет кодировку UTF-8. Не нужно запоминать устройство кодировок: сейчас достаточно правильно использовать готовые функции.

maxlength="100" помогает при обычном вводе, но сервер всё равно проверяет длину. Запрос может прийти без нашей формы. Код 400 означает «условия запроса неверны». Код 500 означает «сервер не смог выполнить работу», например не подключился к базе. Это разные ситуации.

Остановка. Что делать с пустым q: вернуть ошибку или все новости? Все новости. Проверяем данные по правилам конкретной страницы, а не запрещаем любое пустое поле.

5. WHERE — выбираем подходящие строки

SQL — язык запросов к базе. Знакомая команда SELECT читает данные. Допишем условие WHERE, что можно прочитать как «где выполняется условие»: 

SELECT id, title, content, created_at
FROM news
WHERE title LIKE '%Кружок%'
ORDER BY id DESC;

Читаем сверху вниз:

  1. Возьми четыре перечисленных поля.
  2. Из таблицы news.
  3. Оставь строки, в которых заголовок подходит под шаблон.
  4. Покажи строки по убыванию id.

LIKE сравнивает текст с шаблоном. Знак % означает «здесь может быть сколько угодно символов, в том числе ни одного». Шаблон %Кружок% найдёт и «Кружок шахмат», и «Новый Кружок шахмат». Условие действует только на title: слово, которое есть лишь в content, не подойдёт.

Есть ещё знак _: он означает ровно один любой символ. Например, шаблон кот_ подходит слову «коты», но не слову «кот». В нашей работе пользовательский % и _ тоже сохраняют смысл специальных знаков. Поэтому поиск % может вернуть все новости. Это предусмотренное поведение учебного поиска, а не ошибка PDO. Буквальный поиск самих знаков требует отдельной обработки; здесь её не добавляем. Правила шаблонов описаны в документации MySQL о LIKE.

Сравнение больших и маленьких букв зависит от настройки сравнения текста в базе — collation. Поэтому не обещаем, что «Кружок» и «кружок» в любой базе дадут одинаковый результат. Для первых проверок используем точно такое написание, как в тестовых заголовках.

6. PDO: отдельно инструкция, отдельно слово

Предыдущий SQL-фрагмент показывает идею на постоянном слове. Пользовательский ввод передадим отдельно от текста SQL: 

$stmt = $pdo->prepare(
    'SELECT id, title, content, created_at FROM news WHERE title LIKE :q'
);
$stmt->execute(['q' => '%' . $q . '%']);
$news = $stmt->fetchAll(PDO::FETCH_ASSOC);

prepare() готовит инструкцию, а :q обозначает место для одного значения. В execute() передаём само значение. Если $q равно Кружок, выражение '%' . $q . '%' соберёт строку %Кружок%. Точка в PHP соединяет строки.

Представьте бланк поручения: «Найди заголовки по образцу ___». Программа задаёт действие, посетитель заполняет только пропуск. Технически PDO не просто рисует текст на бланке: он передаёт SQL и значения через механизм подготовленных запросов. Аналогия помогает разделить их роли.

Кавычки вокруг :q в SQL не ставим. И не пишем LIKE '%:q%': целый шаблон передаётся значением параметра. В массиве execute() ключ q соответствует имени :q в запросе.

PDO не делает слово «правильным» для нашего задания: длину проверяет PHP. PDO также не отменяет смысл % внутри LIKE. Его задача здесь — безопасно передать значение, включая кавычки. Возможности параметров описаны в руководстве PDO.

Если $q === '', в лабораторной просто не добавляем часть WHERE. Один и тот же файл умеет показывать весь список и результаты поиска.

7. ORDER BY: порядок выбираем из двух разрешённых

ORDER BY id ASC располагает номера по возрастанию: 11, 12, 13. ORDER BY id DESC — по убыванию: 13, 12, 11.

В нашем учебном проекте новые записи получают больший автоматически выданный id. Поэтому называем порядок DESC «Сначала новые». Это договор учебной страницы. Номер не является датой события: при импорте или ручном назначении номеров связь с хронологией может нарушиться. Поле created_at показываем отдельно.

Пользователь не присылает SQL-команду. Он выбирает короткое имя, а программа переводит его по своей таблице: 

$orders = [
    'new' => 'id DESC',
    'old' => 'id ASC',
];

Это список разрешённых значений, или whitelist. После проверки $sort выражение $orders[$sort] даёт один из двух фрагментов, заранее написанных разработчиком: 

$sql .= ' ORDER BY ' . $orders[$sort];

Знак .= означает «добавь строку справа к уже имеющейся строке слева». Если $sort равен old, к запросу добавится ORDER BY id ASC.

Почему не поставить ORDER BY :sort? Параметр PDO передаёт значение, а направление и имя столбца относятся к устройству SQL-команды. Их нельзя подменять обычным параметром. Поэтому слово для поиска передаём через PDO, а порядок выбираем из фиксированного списка. Произвольный текст из адреса к SQL не приклеиваем.

8. Показываем результат и сохраняем условия

После запроса $news — массив найденных записей. Перебираем его знакомым foreach. count($news) сообщает, сколько записей получили. Это число результатов поиска, а не обязательно размер всей таблицы.

Возможны три обычных состояния:

Состояние Что видит посетитель
Записи найдены Количество и список
Запрос корректен, совпадений нет «По вашему запросу ничего не найдено» и HTTP 200
Условия неверны Понятную ошибку и HTTP 400

Ноль совпадений — не ошибка запроса. База успешно ответила: «Подходящих записей нет». При ошибке сервера нельзя показывать «Ничего не найдено»: это создаёт ложное впечатление успешного поиска.

Слово оставляем в поле формы, а выбранный порядок — в списке. Человеку не нужно вспоминать, какие условия привели к результату. Ссылка на news-search.php без параметров сбрасывает условия.

9. Перед выводом текста используем e()

Пользователь может ввести кавычку или <b>. Заголовки из базы тоже могут содержать специальные символы. При выводе в HTML используем знакомую функцию: 

function e(string $value): string {
    return htmlspecialchars($value, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8');
}

Например, value="<?= e($q) ?>" безопасно возвращает запрос в поле формы, а <?= e($item['title']) ?> выводит заголовок текстом. ENT_QUOTES обрабатывает оба вида кавычек, ENT_SUBSTITUTE заменяет некорректные последовательности кодировки. Это поведение описывает руководство PHP по htmlspecialchars.

Две задачи нужно различать: параметр PDO передаёт значение в SQL, а e() выводит его в HTML. Выполнение одной задачи не заменяет другую. Не сохраняем HTML-экранированную версию слова в базу и не используем её вместо поискового запроса.

10. Весь путь одного поиска

Ввели «Кружок» и выбрали «Сначала старые»
    ↓
Браузер отправил GET: q=Кружок, sort=old
    ↓
PHP проверил строку и допустимый порядок
    ↓
PDO передал MySQL запрос и шаблон %Кружок%
    ↓
MySQL вернул подходящие строки в порядке id ASC
    ↓
PHP собрал HTML, браузер показал список

До следующей отправки формы условия не меняются. Здесь нет автоматического поиска при каждом нажатии клавиши: пользователь осознанно нажимает «Найти».

11. Вопросы с короткими ответами

  1. Поиск удаляет неподходящие строки? Нет, они остаются в таблице и лишь не включаются в результат.
  2. Зачем name="q"? Под этим именем браузер передаст значение, а PHP прочитает его из $_GET['q'].
  3. Почему пустое поле допустимо? По нашему договору оно означает просмотр всех новостей.
  4. Что означает % в LIKE? Любую последовательность символов, даже пустую.
  5. Зачем параметры PDO, если мы проверили длину? Короткая строка тоже может содержать кавычки; значение должно передаваться отдельно от SQL.
  6. Почему проверяем sort на сервере? Адрес можно изменить вручную, обойдя варианты формы.
  7. Можно ли передать DESC через :sort? Нет, это часть SQL-команды. Выбираем заранее написанный вариант по whitelist.
  8. Ничего не найдено — это 400? Нет, корректный поиск возвращает 200, даже когда совпадений ноль.
  9. Что делает e()? Подготавливает текст для безопасной вставки в HTML; она не выполняет поиск и не защищает SQL.
  10. Работает ли эта страница без JavaScript? Да, браузер умеет отправлять обычные HTML-формы сам.

В лабораторной №8 соберём страницу из четырёх последовательных блоков и проверим её на небольшом наборе новостей.
