Web-программирование. Лекция 7

JavaScript + PHP: работа с сервером без перезагрузки страницы

1. От HTML-формы к API

В шестой лекции PHP после изменения новости перенаправлял браузер на страницу списка. Теперь оставим страницу открытой: JavaScript отправит запрос, получит результат и обновит нужные DOM-элементы.

Путь данных: событие в браузере → fetch → PHP → MySQL → JSON → DOM. База остаётся на сервере; JavaScript не получает пароль MySQL и не отправляет SQL-запросы напрямую.

2. Договор между клиентом и сервером

API — интерфейс взаимодействия программ. До написания кода нужно договориться об адресах, методах, полях и ошибках. Для небольшого учебного проекта используем один файл api-news.php:

  • GET api-news.php — получить список, ответ 200 и объект {"news": [...]}.
  • POST api-news.php, JSON с action: "create", title, content — добавить запись, ответ 201 и объект {"item": {...}}.
  • POST api-news.php, JSON с action: "delete", id — удалить запись, ответ 200 и объект {"deleted": 5}.

Это простой API с операциями в теле POST. В API, построенном вокруг ресурсов, часто используют адрес /news/5 и метод DELETE. Для нашей работы маршрутизатор не требуется.

Ошибки имеют единый вид: {"error": "Введите заголовок и текст."}. Код 400 обозначает некорректный запрос, 404 — отсутствие записи, 405 — неподдерживаемый метод, 415 — неподдерживаемый формат тела, 422 — ошибку проверки полей, 500 — внутреннюю ошибку сервера.

3. JSON и тело запроса

JSON описывает объекты, массивы, строки, числа, логические значения и null. В JSON ключи и строки заключаются в двойные кавычки; комментарии не допускаются. 

const payload = { action: 'create', title: 'Новая лекция', content: 'Изучаем API.' };
const body = JSON.stringify(payload);

JSON.stringify() превращает объект JavaScript в строку. PHP читает её из php://input: 

$data = json_decode(file_get_contents('php://input'), true, 512, JSON_THROW_ON_ERROR);

Параметр true превращает JSON-объекты в ассоциативные массивы PHP. Ошибку разбора нужно перехватить через catch (JsonException $e). При Content-Type: application/json данные не появляются в $_POST, как при обычной отправке формы.

4. Асинхронность и Promise

Запрос к серверу занимает время. fetch() возвращает Promise — объект будущего результата. Во время ожидания браузер может продолжать реагировать на действия пользователя. 

async function loadNews() {
    const response = await fetch('api-news.php');
    const data = await response.json();
    return data.news;
}

async делает функцию асинхронной: её результат тоже является Promise. await приостанавливает выполнение этой функции до получения результата, а не блокирует всю страницу. Первый await ждёт ответа, второй — чтения тела и разбора JSON.

5. Почему одного catch недостаточно

fetch() обычно отклоняет Promise при сетевой ошибке, но HTTP-ответ 404 или 500 сам по себе не вызывает исключение. Нужно проверить response.ok. 

async function request(options = {}) {
    const response = await fetch('api-news.php', options);
    const data = await response.json();
    if (!response.ok) {
        throw new Error(data.error || `Ошибка HTTP ${response.status}`);
    }
    return data;
}

Если сервер вместо JSON вернул HTML, ошибка возникнет при response.json(). Поэтому API должен выдавать JSON и при неудаче. Подробности ошибок PHP проверяют на сервере, а клиенту отправляют понятное сообщение.

6. Перехват отправки формы

form.addEventListener('submit', async (event) => {
    event.preventDefault();
    const data = new FormData(form);
    try {
        await request({
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({
                action: 'create',
                title: data.get('title'),
                content: data.get('content')
            })
        });
        form.reset();
    } catch (error) {
        message.textContent = error.message;
    }
});

Здесь form и message — заранее найденные DOM-элементы. preventDefault() отменяет обычную отправку формы. FormData читает именованные поля, а JSON.stringify() подготавливает тело запроса. Очищаем форму только после подтверждённого сохранения. Серверная проверка из шестой лекции по-прежнему обязательна.

7. Обновление DOM

Полученные данные нужно превратить в элементы страницы:

function renderNews(news, list) {
    list.replaceChildren();
    for (const item of news) {
        const li = document.createElement('li');
        const title = document.createElement('strong');
        title.textContent = item.title;
        li.append(title);
        list.append(li);
    }
}

textContent вставляет текст. Не подставляйте пользовательские заголовки в innerHTML: браузер может воспринять их как разметку. При пустом массиве покажите «Новостей пока нет», чтобы пользователь отличал пустой список от незавершённой загрузки.

8. Состояния интерфейса

У операции есть начало, успех и ошибка. На время запроса показываем сообщение и отключаем кнопки; в finally обязательно возвращаем возможность работать: 

try {
    button.disabled = true;
    message.textContent = 'Сохраняем…';
    await saveNews(); // функция отправки, определённая в приложении
    message.textContent = 'Новость сохранена.';
} catch (error) {
    message.textContent = error.message;
} finally {
    button.disabled = false;
}

Блокировка уменьшает число случайных повторных отправок, но не заменяет серверные гарантии. Если связь оборвалась после сохранения, клиент может не получить подтверждение. Перед повторным добавлением стоит обновить список.

После успешного изменения можно повторно запросить весь список или обновить его локально на основании ответа API. В лабораторной выберем второй вариант: успешное сохранение не будет зависеть от дополнительного GET-запроса.

9. Отладка через Network

Откройте инструменты разработчика, вкладку Network, фильтр Fetch/XHR. Для запроса проверьте адрес, HTTP-метод, статус, отправленное тело и ответ. Ошибка 422 указывает на проверку данных; HTML вместо JSON часто означает неправильный адрес или ошибку PHP.

HTML-страницу и API открываем через один локальный сайт: одинаковые схема, хост и порт. Двойной щелчок по HTML открывает file://, где серверный PHP не выполняется. Для этого проекта настройка CORS не нужна.
