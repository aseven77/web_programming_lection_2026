Web-программирование. Лекция 6

Формы и CRUD: управление данными на PHP и MySQL

1. От просмотра новостей к управлению сайтом

В четвёртой лекции мы читали новости из таблицы news. Теперь посетитель учебной страницы сможет добавить новость, исправить её текст и удалить ненужную запись. Сохраним знакомые поля: id, title, content, created_at.

Четыре основные операции с данными называют CRUD:

  • Create — создать запись, SQL-команда INSERT.
  • Read — прочитать записи, команда SELECT.
  • Update — изменить запись, команда UPDATE.
  • Delete — удалить запись, команда DELETE.

Обычная HTML-форма работает без JavaScript: браузер отправляет запрос, PHP обрабатывает данные, а браузер получает следующую страницу.

2. Как форма передаёт данные

<form action="admin.php" method="post">
    <input type="hidden" name="action" value="create">
    <label>Заголовок <input name="title" maxlength="255" required></label>
    <label>Текст <textarea name="content" required></textarea></label>
    <button type="submit">Добавить</button>
</form>

action у формы задаёт адрес обработчика. Атрибут name задаёт ключ передаваемого поля. Без него значение элемента не попадёт в обычную отправку формы. Скрытое поле action внутри формы — наше собственное обозначение операции, которое PHP прочитает из $_POST.

GET используем для просмотра: например, admin.php?edit=5 открывает форму новости №5. POST используем для изменения данных. Сам по себе POST не шифрует данные и не проверяет права пользователя.

3. Серверная проверка данных

required помогает пользователю, но запрос можно отправить в обход браузерной формы. Поэтому PHP обязан повторить проверку. 

<?php
$title = is_string($_POST['title'] ?? null) ? trim($_POST['title']) : '';
$content = is_string($_POST['content'] ?? null) ? trim($_POST['content']) : '';
$errors = [];
if ($title === '') {
    $errors[] = 'Введите заголовок.';
} elseif (mb_strlen($title, 'UTF-8') > 255) {
    $errors[] = 'Заголовок должен содержать не более 255 символов.';
}
if ($content === '') {
    $errors[] = 'Введите текст новости.';
}

trim() удаляет пробелы по краям, поэтому строка из одних пробелов считается пустой. is_string() защищает от неожиданного массива вместо строки. Для mb_strlen() необходимо расширение PHP mbstring: оно считает символы UTF-8, а не байты.

При ошибке возвращаем страницу с сообщением и уже введёнными значениями. SQL-запрос выполняем только после успешной проверки.

4. Подготовленные запросы PDO

Нельзя склеивать пользовательский ввод с SQL. Вместо этого текст запроса и значения передаются отдельно: 

$stmt = $pdo->prepare('INSERT INTO news (title, content) VALUES (?, ?)');
$stmt->execute([$title, $content]);

Знаки ? — места для значений. Порядок элементов в execute() совпадает с порядком знаков вопроса. Кавычки вокруг ? не нужны. Параметрами можно передавать значения, но не названия таблиц или столбцов.

Подготовленные запросы решают задачу безопасной передачи значений в SQL. Проверка длины и обязательности полей остаётся отдельной задачей.

5. Чтение записи для редактирования

Сначала проверяем идентификатор, затем запрашиваем запись:

$id = filter_var($_GET['edit'] ?? null, FILTER_VALIDATE_INT,
    ['options' => ['min_range' => 1]]);
if ($id === false || $id === null) {
    http_response_code(400);
    exit('Некорректный идентификатор.');
}
$stmt = $pdo->prepare('SELECT id, title, content FROM news WHERE id = ?');
$stmt->execute([$id]);
$item = $stmt->fetch(PDO::FETCH_ASSOC);
if (!$item) {
    http_response_code(404);
    exit('Новость не найдена.');
}

Положительный числовой идентификатор ещё не гарантирует, что запись существует. Поэтому проверяем результат fetch().

В форму помещаем текущие значения и скрытый id. Скрытое поле пользователь тоже может изменить — ему нельзя доверять без проверки.

6. Обновление и удаление

После проверки идентификатора и содержимого выполняем обновление:

$stmt = $pdo->prepare('UPDATE news SET title = ?, content = ? WHERE id = ?');
$stmt->execute([$title, $content, $id]);

Удаление выполняется отдельной POST-формой:

$stmt = $pdo->prepare('DELETE FROM news WHERE id = ?');
$stmt->execute([$id]);

Условие WHERE определяет, какую запись нужно изменить. Без него UPDATE или DELETE затронет все строки таблицы. Ссылка вида delete.php?id=5 не должна удалять запись по GET: открытие ссылки должно оставаться операцией чтения.

Нулевой rowCount() после UPDATE не всегда означает отсутствие записи: пользователь мог сохранить прежние значения. Не используйте этот результат как единственную проверку существования новости.

7. Безопасный вывод в HTML

Данные в базе храним как текст. При вставке в HTML экранируем специальные символы: 

function e(string $value): string {
    return htmlspecialchars($value, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8');
}

<input name="title" value="<?= e($title) ?>">
<textarea name="content"><?= e($content) ?></textarea>

Так строка <b>Новость</b> будет показана как текст. htmlspecialchars() применяется при выводе в HTML, а подготовленные запросы — при работе с SQL. Это разные задачи.

8. Перенаправление после POST

После успешного сохранения отправляем браузер на страницу списка:

header('Location: admin.php', true, 303);
exit;

Это схема Post/Redirect/Get: POST изменяет данные, ответ 303 направляет браузер выполнить GET. Обновление итоговой страницы повторит чтение, а не добавление записи. При ошибке проверки перенаправление не нужно: показываем ту же форму с подсказками.

header() вызывается до HTML и любого другого вывода. exit завершает обработчик, чтобы последующий код не продолжил выполняться.

9. Границы учебного примера

В лабораторной мы создадим локальную страницу управления без системы пользователей. Публикация такой страницы требует аутентификации, проверки прав на сервере и защиты изменяющих запросов от CSRF. POST и скрытое поле id сами по себе этих задач не решают.
