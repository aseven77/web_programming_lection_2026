Лабораторная работа №14

Git с нуля: история маленького сайта

Лекция №14 · Предыдущая работа: авторизация

Что сделаем

Создадим маленький сайт о питомце и научимся сохранять его развитие в Git. Можно выбрать вымышленного питомца, любимого персонажа или своё хобби — настоящие личные данные не нужны.

В конце у вас будут две HTML-страницы, понятная история коммитов, файл правил игнорирования и отдельная ветка, изменения которой вошли в main.

Время: ориентировочно 90–120 минут. Шаги 1–9 — основа, 10–12 — ветки и самостоятельная работа. Дополнительное задание после них можно выполнить позже.

Перед началом

Нужны Windows, PowerShell, установленный Git 2.28 или новее, редактор кода и браузер. Установка описана в лекции. Интернет нужен только для первоначальной загрузки Git; дальше работаем локально. PHP, база данных, OpenServer и аккаунт GitHub не требуются.

Создавайте новый учебный проект вне папки курса и других репозиториев. Если вы уже повторяли лекцию, для лабораторной заведите новую папку git-pet-lab. Не удаляйте старую историю ради повторения.

Команды вводим в терминал PowerShell, HTML и содержимое других файлов — в редактор. После редактирования нажимаем Ctrl+S. После изменения HTML обновляем страницу в браузере.

Шаг 1. Подготовить папку и терминал

  1. Через Проводник откройте «Документы».
  2. Создайте новую пустую папку git-pet-lab.
  3. В VS Code выберите «Файл → Открыть папку» и откройте именно её.
  4. Выберите «Терминал → Создать терминал», используйте PowerShell.
  5. Выполните по одной строке:
Get-Location
Get-ChildItem
git --version

Проверка: путь оканчивается на git-pet-lab, папка пока пустая, Git отвечает строкой git version .... Если путь другой, снова откройте нужную папку и новый терминал. Если Git не найден, сначала решите установку по лекции.

Не вводите часть приглашения вида PS C:\...> и не копируйте ответы программы как команды.

Шаг 2. Начать историю и указать автора

git init -b main
git config user.name "Student"
git config user.email "student@example.test"
git config --get user.name
git config --get user.email
git status

Можете заменить Student своим учебным именем. Адрес student@example.test вымышленный, для этой локальной работы его достаточно. Команды задают подпись только в текущем репозитории.

Ожидаем: On branch main, No commits yet. История начата, но сохранений пока нет. Если терминал сообщает Reinitialized existing Git repository, проверьте, действительно ли вы выбрали новую папку.

Папка .git может быть скрыта в Проводнике. Не создавайте её вручную и не меняйте её содержимое.

Шаг 3. Создать страницу и первый коммит

В редакторе создайте index.html и вставьте полный код:

<!doctype html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Мой питомец</title>
</head>
<body>
    <h1>Мой кот Барсик</h1>
    <p>Это первая версия моего сайта.</p>
</body>
</html>

Сохраните файл. Убедитесь, что он называется index.html, а не index.html.txt. Откройте его в браузере двойным щелчком.

В терминале:

git status

Проверка до добавления: index.html находится в Untracked files. Теперь:

git add index.html
git status
git diff --staged

Проверка подготовки: index.html находится в Changes to be committed; в разнице виден добавленный HTML. Если открылся просмотрщик с (END), выйдите английской клавишей q.

git commit -m "Создать первую страницу о питомце"
git status
git log --oneline

Ожидаем: один коммит и working tree clean. Сохраните для отчёта его идентификатор из log.

Объясните вслух: что сделали отдельно Ctrl+S, add и commit?

Шаг 4. Изменить страницу и прочитать разницу

Замените только строку <h1> в index.html:

<h1>Кот Барсик — хозяин дома</h1>

Сохраните файл и обновите браузер. Затем:

git status
git diff

Ожидаем: файл помечен modified; в разнице старый заголовок со знаком -, новый — со знаком +.

git add index.html
git diff
git diff --staged
git commit -m "Уточнить заголовок страницы"

Проверка: сразу после add обычный diff пустой, а diff --staged показывает заголовок. После коммита в git log --oneline две записи.

Запишите одним предложением, почему пустой git diff перед коммитом не означал отсутствие изменений вообще.

Шаг 5. Убедиться, что add запоминает конкретный вариант

В index.html перед </body> добавьте строку и сохраните файл:

<p>Барсик любит спать.</p>

git add index.html

Теперь в редакторе замените только что добавленную строку и снова сохраните:

<p>Барсик любит играть.</p>

git status
git diff
git diff --staged

Ожидаем: index.html есть и среди подготовленных, и среди неподготовленных изменений. diff --staged показывает добавление строки про сон. Обычный diff показывает её замену на строку про игры.

Пока не делайте коммит. Сначала заберём в подготовку правильную версию:

git add index.html
git diff --staged
git commit -m "Рассказать о любимом занятии питомца"

Проверка: подготовленная версия перед коммитом говорит про игры; теперь в истории три коммита. Снимок вывода двух видов diff до повторного add пригодится для защиты.

Шаг 6. Убрать изменение из подготовки, сохранив текст

В редакторе создайте файл README.md — короткую инструкцию о проекте. Вставьте:

# Сайт о питомце

Учебный проект для знакомства с Git.

Чтобы открыть сайт, дважды щёлкните по index.html.

Сохраните файл и подготовьте:

git add README.md
git status
git restore --staged README.md
git status

Ожидаем: README.md снова в Untracked files, потому что это новый файл, которого ещё нет ни в одном коммите. Откройте его: весь текст на месте. Мы отменили подготовку, а не создание файла.

Теперь всё-таки сохраним инструкцию в историю:

git add README.md
git commit -m "Добавить инструкцию запуска сайта"

Проверка: четыре коммита, рабочая папка чистая.

Шаг 7. Отменить специально сделанную ошибку

Этот опыт выполняем только после успешного коммита шага 6. Убедитесь через git status, что нет других изменений.

В index.html временно замените заголовок строкой:

<h1>ОШИБКА ДЛЯ ОПЫТА</h1>

Сохраните файл. Не выполняйте git add. Посмотрите, что мы собираемся отбросить:

git diff -- index.html

Если в разнице только эта специально сделанная ошибка, выполните:

git restore index.html
git status

Ожидаем: вернулся заголовок «Кот Барсик — хозяин дома», снова working tree clean, число коммитов осталось четыре. Обновите браузер.

Команда заменила рабочий файл его подготовленной версией; здесь она совпадала с последним коммитом. Реальные нужные правки так отменять нельзя: несохранённый в Git текст может быть потерян.

Если редактор предлагает сохранить старое содержимое поверх изменённого файла, перечитайте файл с диска, чтобы случайно не вернуть ошибку.

Шаг 8. Настроить игнорирование лишнего файла

Создайте в корне проекта файл с точным именем .gitignore, без .txt в конце:

notes-private.txt
*.log
.env

Теперь создайте notes-private.txt с вымышленной заметкой:

Пробная заметка: купить игрушечную мышку.

Сохраните оба файла. Настоящие пароли и личные данные в этом опыте не используйте.

git status
git check-ignore -v notes-private.txt

Ожидаем: status показывает новый .gitignore, но не показывает заметку. check-ignore выводит правило из .gitignore, которое исключило notes-private.txt. При этом сама заметка по-прежнему есть на диске.

git add .gitignore
git commit -m "Добавить правила игнорирования"
git ls-files

git ls-files показывает отслеживаемые файлы. Сейчас это .gitignore, README.md и index.html; заметки среди них нет. В истории пять коммитов.

Если заметка всё-таки отслеживается, значит, её добавили раньше правила. Не пытайтесь исправить это простым добавлением ещё одной строки в .gitignore: покажите результат преподавателю. В основном сценарии заметку не добавляли в индекс.

Шаг 9. Прочитать свою историю

git log --oneline
git show

Ответьте письменно:

  1. Какой коммит был первым? Укажите его короткий идентификатор.
  2. Какое сообщение у самого нового коммита?
  3. Какой файл изменён в последнем коммите?
  4. Почему коммита с заголовком «ОШИБКА ДЛЯ ОПЫТА» в истории нет?

Проверка: пять осмысленных сохранений; новое расположено сверху. git show последнего коммита показывает добавление .gitignore.

На этом основа пройдена. Перед следующим шагом попробуйте объяснить соседу путь «файл → подготовка → коммит» без подсказки.

Шаг 10. Сделать вторую страницу в отдельной ветке

Сначала git status: ожидаем чистое состояние. Затем:

git switch -c about-pet
git branch

Ожидаем: звёздочка возле about-pet. Создайте about.html:

<!doctype html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>О питомце</title>
</head>
<body>
    <h1>О Барсике</h1>
    <p>Барсик любит коробки и солнечные подоконники.</p>
    <a href="index.html">На главную</a>
</body>
</html>

В index.html перед </body> добавьте:

<a href="about.html">Подробнее о питомце</a>

Сохраните оба файла, откройте сайт и проверьте переход туда и обратно.

git add index.html about.html
git diff --staged
git commit -m "Добавить страницу о питомце и навигацию"
git status
git switch main

Ожидаем: в рабочей папке больше нет about.html, а в index.html нет новой ссылки. Обновите главную страницу. Это нормальное содержимое main: шестой коммит пока только в about-pet.

Заметка notes-private.txt остаётся: она игнорируется и не входила в коммиты веток.

Чтобы увидеть обе линии истории:

git log --oneline --all --graph --decorate

--all показывает коммиты всех веток, --graph рисует связи, --decorate показывает подписи веток. Здесь граф может быть прямым: в main после ответвления не было новых коммитов.

Шаг 11. Включить готовую страницу в main

git branch --show-current
git status

Перед слиянием: текущая ветка — main, рабочая папка чистая. Выполните:

git merge about-pet
git status
git log --oneline --all --graph --decorate

Ожидаем: сообщение Fast-forward, файл about.html и ссылка на него вернулись. В main теперь шесть коммитов, а отдельного седьмого коммита слияния в этом сценарии нет.

Откройте index.html, перейдите на вторую страницу и вернитесь. Git объединил изменения, а работу ссылки проверяем сами.

Если вместо ожидаемого результата возник конфликт, остановитесь и прочитайте git status. При точном выполнении шагов конфликт не ожидается; вместе с преподавателем найдите, какие дополнительные правки были сделаны. Не удаляйте .git и не запускайте случайные команды сброса.

Шаг 12. Самостоятельно сделать маленькое улучшение

Оставаясь в main, добавьте на главную страницу список из трёх любимых занятий питомца. Для другой темы придумайте три подходящих пункта.

Без копирования готовой последовательности:

  1. Сохраните файл и посмотрите страницу в браузере.
  2. Проверьте состояние и разницу.
  3. Подготовьте только нужный файл.
  4. Проверьте подготовленные изменения.
  5. Сделайте коммит с собственным понятным сообщением.
  6. Убедитесь, что рабочая папка чистая, а в истории появился новый коммит.

Итог основной работы: не меньше семи осмысленных коммитов, текущая ветка main, вторая страница включена в неё, заметка не отслеживается. Если сделали дополнительные осмысленные коммиты, их может быть больше.

Дополнительно: получить копию без интернета

Это задание не входит в обязательные баллы. Оно показывает смысл clone без регистрации на сервисах.

После завершения основной работы в терминале, находящемся в git-pet-lab, выполните:

cd ..
git clone git-pet-lab git-pet-copy
cd git-pet-copy
git log --oneline
git status
git remote -v

Папка git-pet-copy до начала должна отсутствовать. Если она уже есть, выберите другое новое имя и используйте его в обеих соответствующих командах; чужую папку не удаляйте.

Ожидаем: в копии есть страницы и история, а notes-private.txt нет. Источником origin будет локальный путь к исходному репозиторию. clone переносит историю и получает рабочие файлы из коммита, а не копирует весь мусор из соседней папки.

Это опыт на одном диске, поэтому защитой от его поломки такая копия не является. Для сдачи возвращайтесь к исходной папке git-pet-lab.

Если что-то не получается

Сообщение или ситуация Что проверить
git не распознан Установлен ли Git; перезапущены ли PowerShell и редактор после установки
unknown switch b при init или неизвестная switch/restore Версию Git; для примеров нужен 2.28 или новее
not a git repository Текущую папку через Get-Location; был ли здесь git init
Author identity unknown Повторить две настройки user.name и user.email в текущем репозитории
pathspec ... did not match any files при add Сохранён ли файл, совпадает ли имя, нет ли окончания .txt, правильная ли текущая папка
nothing to commit Было ли реальное изменение, сохранён ли файл, выполнен ли add; посмотреть status
diff пустой Возможно, изменение уже подготовлено; посмотреть diff --staged и status
Файл сразу в двух разделах status После add его снова изменили; сравнить оба вида diff
warning: LF will be replaced by CRLF Предупреждение о переносах строк, не потеря текста; проверить, что команда завершилась и status ожидаемый
Внизу (END), команды не вводятся Нажать английскую q, чтобы выйти из просмотра
После switch main исчез about.html До слияния это ожидаемо: файл сохранён в другой ветке
Your local changes ... would be overwritten Есть незакоммиченные правки; посмотреть status, сохранить нужную работу коммитом и повторить переключение
.gitignore не исключает заметку Точное имя файла правил, сохранение файла, не добавлена ли заметка в Git раньше
Браузер показывает старый текст Сохранить файл и обновить страницу; проверить, какой файл открыт, особенно после clone

При непонятной ошибке сохраните её полный текст и вывод git status. Они полезнее, чем повторный запуск всех команд подряд.

Что сдать

  1. Папку исходного проекта git-pet-lab с .git, .gitignore, README.md, index.html, about.html. Можно передать ZIP, но проверьте, что скрытая .git действительно попала в архив: без неё преподаватель не увидит историю. Учебную заметку прикладывать необязательно.
  2. Короткий отчёт отдельным файлом вне папки проекта: ответы из шага 9 и объяснение отличий Ctrl+S, add, commit.
  3. Скриншоты или текст вывода: оба вида diff в шаге 5 до повторного add; итоговые git status, git log --oneline --all --graph --decorate, git ls-files и git check-ignore -v notes-private.txt.
  4. Скриншот главной страницы и второй страницы после слияния.

Не заменяйте репозиторий одним скриншотом сайта: в этой работе оценивается ещё и история. Интернет-публикация и ссылка на GitHub не обязательны.

Критерии — 10 баллов

Результат Баллы
Репозиторий создан, указан автор, обе HTML-страницы открываются 2
Не меньше семи осмысленных коммитов, понятные сообщения, студент читает историю 2
Студент показывает разницу между рабочим файлом и подготовленным вариантом 2
Продемонстрированы отмена подготовки и отмена специально сделанной ошибки 1
.gitignore сохранён в истории, заметка не отслеживается 1
Создана ветка, её изменения включены в main, переходы между страницами работают 2

Работа завершена, когда репозиторий можно открыть на проверке, а студент объясняет, что сохранял на каждом этапе. Отдельный коммит слияния и GitHub для получения 10 баллов не нужны.
