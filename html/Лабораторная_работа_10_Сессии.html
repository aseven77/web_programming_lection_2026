Лабораторная работа №10

Сессии PHP и список «Прочитать позже»

Лекция 10: объяснение темы · Предыдущая лекция: пагинация

Что сделаем

Создадим reading-list.php: все новости небольшого учебного набора и кнопки «Прочитать позже» и «Убрать отметку». После обновления страницы выбор сохранится в сессии этого браузера.

Новости по-прежнему лежат в базе site, таблице news. Мы только читаем её. Добавление или удаление отметки не изменяет строки таблицы. Регистрация, пароль и JavaScript для этой работы не нужны.

Путь действия: кнопка → POST → проверка → изменение сессии → переход 303 → страница с отметкой.

Перед началом: пять маленьких проверок

  1. Запустите локальные PHP 8 и MySQL через Open Server или XAMPP.
  2. Откройте через сервер рабочую страницу новостей из лабораторной №4, №8 или №9. Она должна читать базу.
  3. Используйте рабочий config.php, который создаёт объект $pdo, со своими настройками подключения.
  4. В таблице site.news должны быть поля id, title, content, created_at и хотя бы две существующие новости. Если основы ещё не готовы, сначала выполните лабораторную №4.
  5. В config.php не должно быть HTML, echo и пробелов до <?php. Файл с одним подключением оставляйте без закрывающего ?>.

Структура нужной части проекта:

папка вашего сайта/
├── config.php          ← уже работает, создаёт $pdo
├── news-search.php     ← работа №8, если выполнена
├── news-pages.php      ← работа №9, если выполнена
└── reading-list.php    ← новый файл этой работы

Здесь читаем весь небольшой учебный набор. Для большой таблицы потребуется другой способ загрузки.

Как собирать файл

Ниже пять блоков полного файла. Копируйте их подряд в reading-list.php: 1 → 2 → 3 → 4 → 5.

Первый блок открывает PHP. Второй и третий продолжают тот же PHP-код. Четвёртый закрывает PHP и начинает HTML. Пятый завершает страницу.

Проверочные команды после блоков временные: удаляйте их перед следующим шагом. Строки с тройными обратными кавычками в .php не копируйте.

Шаг 1. Открыть сессию и подготовить ячейки

Создайте reading-list.php в кодировке UTF-8 без BOM. Первый символ файла — < из <?php.

Блок 1 из 5 — начало reading-list.php: 

<?php
session_start();
require __DIR__ . '/config.php';

function e(string $value): string {
    return htmlspecialchars($value, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8');
}

if (!isset($_SESSION['reading_list']) || !is_array($_SESSION['reading_list'])) {
    $_SESSION['reading_list'] = [];
}

if (!isset($_SESSION['reading_csrf']) || !is_string($_SESSION['reading_csrf'])) {
    $_SESSION['reading_csrf'] = bin2hex(random_bytes(32));
}

$error = '';

Что здесь происходит

session_start() открывает хранилище этой сессии. PHP узнаёт её по идентификатору, который браузер обычно передаёт в cookie. require подключает уже готовый файл с $pdo. __DIR__ — папка текущего файла, точка . соединяет части пути.

Функция e() безопасно выводит текст в HTML. string $value означает «ожидаем строку», : string — «возвращаем строку». htmlspecialchars() превращает HTML-символы в текст; флаги обрабатывают кавычки и некорректные символы. Функцию применяем к тексту карточек и значениям полей.

Условие !isset(...) || !is_array(...) читается: «ячейки ещё нет или в ней лежит не массив». Знак || означает «или», ! — «не». Только в этом случае создаём пустой список. На следующих запросах существующий выбор сохраняется.

reading_csrf — отдельная ячейка со случайным токеном формы. Это технический контрольный код, а не идентификатор сессии. random_bytes(32) получает случайные байты, bin2hex(...) делает из них удобную строку. Подробнее разберём проверку токена на шаге 3.

Маленькая проверка

Временно допишите echo 'Шаг 1 готов';. Откройте файл по адресу своего сервера, например http://имя-вашего-сайта/reading-list.php, не через file:///.

Ожидайте «Шаг 1 готов» без предупреждений. Затем удалите echo: он помешает будущему перенаправлению.

Если видите Failed to read session data, проверьте журнал PHP и доступность папки сессий в настройках локального сервера. Если ошибка относится к PDO, сначала восстановите рабочий config.php.

Шаг 2. Получить новости и их номера

Блок 2 из 5 — сразу после блока 1, без нового <?php: 

$stmt = $pdo->query(
    'SELECT id, title, content, created_at FROM news ORDER BY id DESC'
);
$news = $stmt->fetchAll(PDO::FETCH_ASSOC);

$existingIds = [];
foreach ($news as $item) {
    $existingIds[(int) $item['id']] = true;
}

foreach ($_SESSION['reading_list'] as $savedId => $selected) {
    if (!isset($existingIds[$savedId])) {
        unset($_SESSION['reading_list'][$savedId]);
    }
}

SQL-запрос только читает данные. ORDER BY выводит свежие новости первыми; id DESC задаёт понятный порядок для совпадающих дат. В запросе нет данных из формы, поэтому здесь достаточно query().

fetchAll(PDO::FETCH_ASSOC) возвращает массив строк таблицы. У каждой строки есть именованные поля, например $item['title'].

Первый foreach делает справочник существующих номеров: 5 → true, 12 → true. (int) превращает номер в целое число. Позже проверим по справочнику существование новости.

Второй foreach убирает отметки новостей, ранее удалённых через другую страницу. $savedId — ключ (номер), $selected — значение отметки. Стрелка => позволяет получить и ключ, и значение. Таблица не изменяется.

Маленькая проверка

Временно добавьте echo count($news);. Число должно совпасть с количеством строк таблицы news. Затем удалите этот echo.

Если число равно нулю, проверьте имя базы в config.php и данные в phpMyAdmin. Для проверки кнопок нужны две новости из предыдущих работ.

Шаг 3. Проверить POST и изменить только отметку

Браузер отправит csrf, action, id. Даже скрытые поля можно поменять через инструменты разработчика, поэтому сервер их проверит.

План обработчика:

  1. Если пришёл POST, проверить контрольный код формы.
  2. Проверить, что операция известна, а номер — положительное целое число.
  3. Проверить, что такая новость существует.
  4. При успехе поставить или убрать отметку и перейти к просмотру страницы.
  5. При ошибке показать сообщение, сохранив выбор.

Блок 3 из 5 — сразу после блока 2:

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $token = $_POST['csrf'] ?? '';
    $action = $_POST['action'] ?? '';
    $rawId = $_POST['id'] ?? '';
    $id = false;

    if (is_string($rawId)) {
        $id = filter_var($rawId, FILTER_VALIDATE_INT,
            ['options' => ['min_range' => 1]]);
    }

    if (!is_string($token) || !hash_equals($_SESSION['reading_csrf'], $token)) {
        http_response_code(403);
        $error = 'Форма устарела или её код неверен. Обновите страницу и попробуйте снова.';
    } elseif (!is_string($action) || ($action !== 'add' && $action !== 'remove')) {
        http_response_code(422);
        $error = 'Неизвестная операция. Используйте кнопки под новостью.';
    } elseif ($id === false) {
        http_response_code(422);
        $error = 'Номер новости должен быть целым положительным числом.';
    } elseif (!isset($existingIds[$id])) {
        http_response_code(404);
        $error = 'Такой новости больше нет. Обновите список.';
    } else {
        if ($action === 'add') {
            $_SESSION['reading_list'][$id] = true;
            $_SESSION['reading_message'] = 'Новость добавлена в список «Прочитать позже».';
        } else {
            unset($_SESSION['reading_list'][$id]);
            $_SESSION['reading_message'] = 'Отметка убрана. Сама новость осталась на сайте.';
        }

        header('Location: reading-list.php', true, 303);
        exit;
    }
}

Читаем новый синтаксис без спешки

$_SERVER['REQUEST_METHOD'] содержит метод запроса. Сравнение === 'POST' проверяет именно POST. GET не запускает добавление и удаление отметок.

$_POST['id'] ?? '' означает «поле id, а если его нет или оно равно null, то пустая строка». ?? не проверяет содержимое поля.

$id = false сначала обозначает «правильного номера пока нет». Проверка is_string($rawId) не пропускает массивы. filter_var с FILTER_VALIDATE_INT принимает целое число, а min_range ограничивает его снизу единицей. Текст abc, число 0 и число -5 не подходят.

elseif означает «иначе, если». Первая обнаруженная ошибка останавливает путь к изменению списка. !== означает «не равно без преобразования типов», && — «и»: неправильное действие не равно ни add, ни remove.

$_SESSION['reading_list'][$id] = true записывает отметку по номеру новости. Повторная запись по этому ключу не создаёт дубликат. unset(...) убирает отметку.

http_response_code(...) задаёт код ответа: 403 — отклонён токен, 422 — неправильное поле, 404 — нет новости. Ниже страница покажет текст $error.

Почему здесь нужен токен

Чужая страница может попытаться отправить форму на наш сайт через браузер посетителя. В определённых условиях браузер приложит cookie автоматически. Мы требуем ещё и случайный код нашей формы, связанный с сессией. Это защищает изменяющий запрос от CSRF.

Сначала is_string($token) проверяет тип. Если пришёл массив, срабатывает первая часть условия и PHP не вызывает hash_equals с неправильным типом. При строке hash_equals сравнивает сохранённый токен с полученным. Токен не подтверждает личность посетителя и не является системой входа. OWASP: Synchronizer Token Pattern, PHP Manual: hash_equals.

Почему после успеха нужен переход

header(..., 303) отправляет браузер на страницу просмотра по GET, exit завершает обработчик. При F5 повторится просмотр страницы. Это схема Post/Redirect/Get. Она применяется после успеха; ошибки показываются сразу в ответе на POST.

Маленькая проверка

Открытие страницы по GET даёт пустой экран без предупреждений: HTML ещё нет. Добавление ?action=add&id=1 к адресу не должно ставить отметку. Кнопки проверим после сборки файла.

Шаг 4. Начать HTML и показать сообщения

Блок 4 из 5 — сразу после блока 3:

$count = count($_SESSION['reading_list']);
$message = $_SESSION['reading_message'] ?? '';
unset($_SESSION['reading_message']);
?>
<!doctype html>
<html lang="ru">
<head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Прочитать позже</title>
</head>
<body>
<main>
    <h1>Новости: прочитать позже</h1>
    <p>Отложено новостей: <strong><?= $count ?></strong></p>
    <p>Отметки относятся к сессии этого браузера.</p>

    <?php if ($error !== ''): ?>
        <p role="alert"><?= e($error) ?></p>
    <?php endif; ?>

    <?php if ($message !== ''): ?>
        <p role="status"><?= e($message) ?></p>
    <?php endif; ?>

    <?php if ($news === []): ?>
        <p>Новостей пока нет. Когда они появятся, их можно будет отложить.</p>
    <?php endif; ?>

$count содержит число отметок. $message читаем из сессии и удаляем оттуда. В обычной переменной текст остаётся до конца запроса, поэтому сообщение показывается один раз.

?> переключает нас из PHP в HTML. Запись <?= ... ?> выводит значение. Конструкция if (...): ... endif; удобна, когда внутри условия находится HTML; по смыслу это обычный if.

role="alert" помечает сообщение об ошибке, role="status" — результат действия. Эти атрибуты помогают вспомогательным технологиям понимать назначение сообщений.

Маленькая проверка

Ожидайте заголовок и число отметок, обычно 0. HTML пока не завершён. Если виден исходный PHP-код, файл открыт без PHP-сервера.

foreach повторяет карточку для каждой новости. $isSelected хранит true или false: есть ли номер этой новости среди выбранных. Условие выводит соответствующий текст.

Проверьте таблицу news через phpMyAdmin: число записей, заголовки и тексты после этих действий не изменились. Сессия хранит выбор отдельно от новостей.

Обычные вкладки одного профиля разделяют cookie. Окна одного сеанса инкогнито тоже могут разделять свои cookie. Сравнивайте обычный режим с инкогнито.

Посмотреть POST → 303 → GET

Откройте инструменты разработчика браузера → Network / Сеть. Включите Preserve log / Сохранять журнал, затем нажмите кнопку добавления. Найдите запрос POST к reading-list.php с ответом 303, а за ним запрос GET к той же странице с ответом 200.

Если после успешного действия остался POST с 200, проверьте, дошёл ли код до header(...) и нет ли преждевременного вывода. При ошибке проверки вместо перенаправления ожидается ответ 403, 404 или 422 с текстом ошибки.

Шаг 7. Проверить неверные данные без изменения PHP-кода

Меняем только форму в своём браузере, не PHP-файл. Новая загрузка страницы вернёт исходный HTML.

  1. Нажмите F12 → Elements / Элементы. Через поиск Ctrl+F найдите name="id" у одной из форм.
  2. Поменяйте только её value, например с 5 на abc.
  3. Нажмите кнопку именно этой карточки. Должно появиться сообщение о неправильном номере, ответ 422; счётчик не меняется.
  4. Перед каждым опытом откройте чистый адрес reading-list.php через адресную строку: получите исходную форму по GET без повторения ошибочного POST.

Так мы проверяем, что PHP справляется и с запросами, которых обычная форма не предлагает.

Если сессия не сохраняется и PHP показывает предупреждение о записи, посмотрите журнал локального сервера и настройку папки сессий. Скрывать предупреждение знаком @ не нужно: сначала устраните причину.

Что важно понимать о сроке хранения

Закрытие вкладки не очищает сессию автоматически. Браузер хранит cookie по своим правилам, сервер очищает старые данные по своим. Восстановление сеанса браузера тоже влияет на поведение. Поэтому в отчёте не пишите «список гарантированно существует до закрытия вкладки».

Корректный вывод для этой работы: «Выбор сохраняется между запросами, пока браузер передаёт идентификатор доступной серверной сессии». Это временный список одного браузерного профиля, без синхронизации между устройствами. PHP Manual: параметры сессий, MDN: cookie.

Небольшое самостоятельное задание

Измените сообщение под заголовком: при нуле отметок показывайте «Вы ещё ничего не отложили», а при числе больше нуля — «Можно вернуться к выбранным новостям позже». Используйте уже знакомый if, не меняя обработчик формы.

После изменения ещё раз выполните только две проверки: пустой список и список с одной отметкой. Более сложное оформление не требуется.

Что сдать

  1. reading-list.php и учебный config.php с локальными реквизитами, без паролей внешних сервисов.
  2. Краткий отчёт с ФИО, группой, темой и адресом запуска локальной страницы.
  3. Скриншоты: две отмеченные новости; состояние после удаления одной отметки; обычное окно и инкогнито с разным выбором.
  4. Скриншот Network с последовательностью POST → 303 → GET.
  5. Таблицу проверок шагов 6–7 с результатами и сообщения об ошибках неверного номера и отсутствующего токена.
  6. Снимки news до и после проверки: число строк и содержимое не изменились.
  7. Вывод на 3–5 предложений: где находятся новости, отметки и что хранит cookie.

Не создавайте новую таблицу и не добавляйте поле selected в news: выбор хранится в сессии.

  3. Зачем создание пустого массива находится внутри условия?
  4. Почему повторная запись по ключу $id не создаёт дубликат?
