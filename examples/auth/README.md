# Примеры к лабораторным №11–13

Локальный учебный сайт на PHP 8.0, PDO и MySQL/MariaDB. Содержит регистрацию, вход, профиль, выход, роли и защищённые формы/API новостей. Все файлы — обычные PHP, HTML и JavaScript, без фреймворка и без ООП-блока.

## Порядок работы

1. Используйте отдельную локальную копию учебного сайта. Нужны PHP 8.0 с `pdo_mysql` и `mbstring`, MySQL/MariaDB, браузер.
2. Если существующий `config.php` уже создаёт `$pdo`, скопируйте его сюда. Иначе скопируйте `config.example.php` в `config.php` и задайте свои настройки. Файл с реальными настройками не сдавайте и не публикуйте.
3. В phpMyAdmin создайте базу `site`, если её ещё нет, и выберите её. Выполните `schema.sql` для пользователей. Если таблицы новостей нет, выполните `news.sql`. `IF NOT EXISTS` не обновляет существующие структуры: сверяйте столбцы с SQL.
4. Откройте `register.php` через локальный сервер, создайте две учебные записи.
5. Откройте `login.php`, войдите, проверьте `profile.php` и кнопку выхода.
6. Для №13 через phpMyAdmin назначьте одной конкретной записи `role='admin'`, как показано в лабораторной. Откройте `admin.php` или `news-app.html` в том же браузере и на том же origin.

Если проект находится по адресу `http://имя-сайта/`, эта папка может открываться как `http://имя-сайта/examples/auth/register.php`. Настройки домена зависят от вашего локального сервера.

## Какие файлы относятся к занятиям

| Работа | Файлы |
|---|---|
| 11 | `schema.sql`, `config.example.php`, `bootstrap.php`, `register.php` |
| 12 | `auth.php`, `login.php`, `profile.php`, `logout.php` |
| 13 | `access.php`, защищённые `admin.php`, `api-news.php`, `news-app.html`, `news-app.js` |

`admin.php` сохраняет CRUD из №6. API сохраняет чтение, добавление и удаление из №7. Чтение публичное, изменения требуют роли `admin` и CSRF-токена. В API токен приходит при GET для администратора и отправляется заголовком `X-CSRF-Token` при POST. После входа обновите список.

Не оставляйте старые незащищённые обработчики доступными в той же обслуживаемой папке: защищённая копия не закрывает старый адрес. Резервные копии держите вне web-каталога.

Полный выход очищает текущую сессию, включая временный список №10, если используется одна сессия. Выход на всех устройствах не реализован.

## Границы примера

Это комплект для локальных занятий. Нет подтверждения email, восстановления пароля, ограничения попыток входа, срока бездействия сессии или MFA. Для публичного размещения нужны отдельная доработка безопасности, HTTPS и поддерживаемая версия PHP. Сообщение о занятом email в учебной регистрации раскрывает факт существования записи.

## Для преподавателя

Исходники страниц используются и в кодовых блоках новых лабораторных: `scripts/build-html.cjs` обновляет блоки между маркерами `example`. Команда `node scripts/prepare-auth-examples.cjs` пересобирает только адаптированные примеры CRUD/API из материалов №6–7.

Сборка курса: `node scripts/build-html.cjs путь/к/marked.esm.js`. Без аргумента используется временная установка `marked` в `%TEMP%/md-html-converter-20261010/node_modules/marked/lib/marked.esm.js`. При её отсутствии установите конвертер командой PowerShell:

```powershell
npm.cmd install --prefix "$env:TEMP\md-html-converter-20261010" --no-audit --no-fund --ignore-scripts marked
node scripts/build-html.cjs
```

Скрипт проверяет существование локальных ссылок и сортирует оглавление по номерам. HTML хранится в `html/`, который уже исключён из Git настройками этого курса.

Проверка PHP и HTTP-сценариев: `node scripts/check-auth.cjs`. Нужен Node.js 22+, PHP 8.0 и MariaDB 10.4 из OpenServer. При других путях задайте переменные `COURSE_PHP` (путь к php.exe) и `COURSE_MARIADB` (папка bin). Скрипт создаёт отдельную временную базу и копию примеров, выбирает свободные localhost-порты и останавливает тестовые процессы после выполнения. Рабочая база `site` не используется. Папка с тестовыми данными и журналами остаётся во временном каталоге, её путь выводится в конце.
