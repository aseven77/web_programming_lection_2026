# Лабораторная работа №12

## Вход, личный профиль и выход

[Лекция №12](Web-программирование_Лекция_12_Аутентификация.md) · [Предыдущая работа: регистрация](Лабораторная_работа_11_Регистрация.md) · [Следующая работа: права доступа](Лабораторная_работа_13_Авторизация.md)

## Что сделаем

Пользователь из таблицы `users` сможет войти по email и паролю, открыть свой профиль и выйти. Гость не сможет получить профиль прямым запросом по адресу.

## Перед началом

Нужны выполненная работа №11, PHP 8.0 с `pdo_mysql` и `mbstring`, рабочие `config.php` и `bootstrap.php`, хотя бы одна зарегистрированная учебная запись с известным вам паролем. Не вставляйте пароль напрямую в `users.password_hash`.

```text
ваш сайт/
├── config.php
├── bootstrap.php
├── register.php
├── auth.php       ← поиск текущего пользователя
├── login.php      ← форма входа
├── profile.php    ← закрытая страница
└── logout.php     ← обработчик выхода
```

Готовые версии доступны в [комплекте примеров](examples/auth/README.md). `bootstrap.php` из №11 не переписываем и повторный `session_start()` в страницы не добавляем.

## Шаг 1. Научить сайт находить текущего пользователя

Создайте **полный файл `auth.php`**:

<!-- example:auth.php -->

```php
<?php
require_once __DIR__ . '/bootstrap.php';

function auth_user(): ?array {
    global $pdo;
    $id = $_SESSION['user_id'] ?? null;
    if (!is_int($id) || $id < 1) {
        return null;
    }
    $stmt = $pdo->prepare('SELECT id, name, email, role FROM users WHERE id = ?');
    $stmt->execute([$id]);
    $user = $stmt->fetch(PDO::FETCH_ASSOC);
    if (!$user) {
        unset($_SESSION['user_id']);
        return null;
    }
    return $user;
}

function auth_require_user(): array {
    $user = auth_user();
    if ($user === null) {
        header('Location: login.php', true, 303);
        exit;
    }
    return $user;
}
```

<!-- /example -->

### Как читать код

`auth_user()` берёт `user_id` из серверной сессии. Число записывает наш обработчик входа, а не форма посетителя. Если номера нет, возвращается `null`. Если он есть, PDO читает пользователя из базы.

`?array` означает «массив или null». В запросе намеренно нет `password_hash`: профиль не нуждается в хеше. Если запись удалена из базы, убираем устаревший `user_id` из сессии.

`auth_require_user()` либо возвращает найденный массив, либо направляет гостя на вход и останавливает обработчик. `global $pdo` использует общее подключение, уже созданное в `config.php`.

**Маленькая проверка:** откройте `auth.php` через сервер. Это файл функций, поэтому пустой ответ без ошибки — ожидаемый результат.

## Шаг 2. Создать вход: серверная часть

В `login.php` будет два блока. **Блок 1 из 2:**

<!-- example:login.php#server -->

```php
<?php
require_once __DIR__ . '/auth.php';
if (auth_user() !== null) {
    header('Location: profile.php', true, 303);
    exit;
}
$error = '';
$email = '';

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    auth_check_post();
    $email = strtolower(trim(auth_field($_POST, 'email')));
    $password = auth_field($_POST, 'password');
    $user = false;
    if (strlen($email) <= 191 && filter_var($email, FILTER_VALIDATE_EMAIL) &&
        strlen($password) >= 12 && strlen($password) <= 72 && strpos($password, "\0") === false) {
        $stmt = $pdo->prepare('SELECT id, password_hash FROM users WHERE email = ?');
        $stmt->execute([$email]);
        $user = $stmt->fetch(PDO::FETCH_ASSOC);
    }
    // Учебный резервный хеш уменьшает различие времени для неизвестного email.
    $hash = $user ? $user['password_hash'] : '$2y$10$92IXUNpkjO0rOQ5byMi.Ye4oKoEa3Ro9llC/.og/at2uheWG/igi.';
    $validPassword = password_verify($password, $hash);
    if ($user && $validPassword) {
        session_regenerate_id(true);
        $_SESSION['user_id'] = (int) $user['id'];
        $_SESSION['auth_csrf'] = bin2hex(random_bytes(32));
        header('Location: profile.php', true, 303);
        exit;
    }
    $error = 'Неверный email или пароль.';
}
?>
```

<!-- /example -->

### Что происходит

1. Уже вошедшего пользователя направляем в профиль.
2. Для POST проверяем CSRF, затем email и пароль.
3. Ищем учётную запись параметризованным запросом.
4. `password_verify()` проверяет пароль по хешу.
5. При успехе меняем идентификатор сессии, сохраняем целочисленный `user_id`, обновляем токен.
6. При неудаче показываем одинаковую ошибку для неверного пароля и неизвестного email.

Резервный хеш нужен только для проверки при отсутствии пользователя. Условие `$user && $validPassword` не позволяет войти через него. Он не является паролем какого-либо созданного администратора.

В этом примере нет ограничения частоты входов: это упражнение для локального сервера, не законченная публичная система аутентификации.

## Шаг 3. Добавить форму входа

**Блок 2 из 2** — добавьте после первого:

<!-- example:login.php#html -->

```php
<!DOCTYPE html>
<html lang="ru">

    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Вход</title>

    <input type="hidden" name="csrf" value="<?= auth_e(auth_csrf()) ?>">
```

<!-- /example -->

**Маленькая проверка:** откройте `login.php`, введите зарегистрированный email и заведомо неправильный пароль. Ожидается сообщение «Неверный email или пароль», email остаётся, пароль не возвращается в HTML. С правильным паролем пока не входите — сначала создадим профиль.

## Шаг 4. Создать защищённый профиль

Создайте **полный файл `profile.php`**:

<!-- example:profile.php -->

```php
<?php
require_once __DIR__ . '/auth.php';
$user = auth_require_user();
header('Cache-Control: no-store');
?>
<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Мой профиль</title>
</head>
<body>
<h1>Здравствуйте, <?= auth_e($user['name']) ?>!</h1>
<p>Email: <?= auth_e($user['email']) ?></p>
<p>Роль: <?= auth_e($user['role']) ?></p>
<form method="post" action="logout.php">
    <input type="hidden" name="csrf" value="<?= auth_e(auth_csrf()) ?>">
    <button type="submit">Выйти</button>
</form>
</body>
</html>
```

<!-- /example -->

Проверка стоит до HTML. Имя, email и роль экранируются. В профиле нет поля с хешем и нет возможности выбрать другой `user_id` из URL. `Cache-Control: no-store` запрещает сохранять ответ как обычную кешируемую страницу.

**Маленькая проверка:** в браузере без входа откройте `profile.php` напрямую. В Network должен быть 303 на `login.php`; HTML профиля не должен отправляться гостю.

## Шаг 5. Создать выход

Создайте **полный файл `logout.php`**:

<!-- example:logout.php -->

```php
<?php
require_once __DIR__ . '/bootstrap.php';
auth_check_post();
$_SESSION = [];
$params = session_get_cookie_params();
setcookie(session_name(), '', [
    'expires' => time() - 3600,
    'path' => $params['path'],
    'domain' => $params['domain'],
    'secure' => $params['secure'],
    'httponly' => $params['httponly'],
    'samesite' => $params['samesite'],
]);
session_destroy();
header('Location: login.php', true, 303);
exit;
```

<!-- /example -->

`$_SESSION = []` очищает данные, `setcookie()` с прошедшим сроком удаляет cookie, `session_destroy()` удаляет серверную сессию. Путь и домен cookie берём из текущих настроек, чтобы удалять именно нужную cookie.

До этих действий стоят проверки POST и CSRF. Если набрать `logout.php` в адресной строке, получится GET и ответ 405 — это правильный результат. Выход выполняется кнопкой профиля.

## Шаг 6. Пройти полный путь

1. Откройте вход и войдите учётной записью из №11.
2. Увидите имя, email, роль `user` и кнопку выхода.
3. Обновите профиль: пользователь остаётся вошедшим.
4. Откройте профиль в новой обычной вкладке того же браузерного профиля: состояние общее.
5. Нажмите «Выйти». Ожидайте POST → 303 → `login.php`.
6. Снова запросите `profile.php` или обновите старую вкладку. Ожидайте переход на вход.

**Проверка смены идентификатора:** в DevTools откройте Application/Storage → Cookies. Сравните `PHPSESSID` до успешного входа и после: значение должно измениться. Не публикуйте сами значения в отчёте — достаточно отметить факт изменения. Имя cookie может отличаться при иной настройке PHP.

## Шаг 7. Проверить отрицательные сценарии

| Действие | Ожидаемый результат |
|---|---|
| Войти с неизвестным email | Та же ошибка, что при неверном пароле |
| Отправить вход без `csrf` | 403, вход не выполнен |
| Открыть профиль гостем по прямой ссылке | 303 на вход |
| Войти в одном браузере и открыть профиль в другом | Второй браузер остаётся гостем |
| Передать `profile.php?user_id=999` | Профиль текущего пользователя, параметр игнорируется |
| Открыть `logout.php` через GET, будучи вошедшим | 405, сессия остаётся активной |
| Удалить токен из формы выхода и отправить | 403, сессия остаётся активной |
| Выполнить правильный выход и вновь запросить профиль | Профиль недоступен |
| Открыть регистрацию до входа, затем войти в другой вкладке и отправить старую форму | 403 из-за смены токена; после обновления формы можно повторить |

Для независимых сессий надёжнее использовать разные браузеры или профили. Несколько окон инкогнито могут использовать общие приватные cookie.

## Типичные ошибки

| Симптом | Что исправить |
|---|---|
| Цикл «вход → профиль → вход» | Проверить сохранение cookie, адрес и флаг `secure` на локальном HTTP |
| Неверный пароль даже для новой записи | Проверить длину сохранённого хеша и использование `password_verify()` |
| `Headers already sent` | Все проверки и заголовки должны стоять до HTML; убрать BOM и echo |
| После GET выхода ничего не произошло | Так задумано: используйте POST-форму |
| Пропал список №10 после выхода | При общей сессии полный выход очищает и временные отметки |
| Видна старая страница по кнопке «Назад» | Сделать новый запрос; оценивать ответ сервера, а не старое изображение страницы |

## Самостоятельная работа

1. Добавьте в регистрацию ссылку на `login.php` теперь, когда файл существует.
2. Создайте ещё одну закрытую страницу `account-help.php`, используя `auth_require_user()`. Проверьте гостевой доступ.
3. Со звёздочкой: смените имя учебного пользователя в БД и обновите профиль. Объясните, почему новое имя видно без повторного входа.
